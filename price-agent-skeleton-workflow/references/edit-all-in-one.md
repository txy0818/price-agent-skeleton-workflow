# 修改提示词（全流程规范）

本文件只定义从 EDIT 意图到展示修改提案的完整执行规范；提案后的"展开完整提示词"、
"确认/同意/保存/创建草稿"由 `SKILL.md` 重新识别意图并路由到对应流程。EDIT 生成过程中禁止读取
其他 reference、历史完整提示词或示例文件作为生成范式。格式只能来自本文件第
[3.5 候选提示词格式模板（当前规则同步 + 格式重构硬分支）] 节。

> **命中即执行**：同一轮执行到校验工具和提案；用户说"新建"仍是基于当前版本派生草稿，`writeMode=EDIT`。

---

## 0. EDIT 可见回复封口（全流程最高优先级）

EDIT 的意图判定、版本绑定、查询、账本推导、候选生成、校验和自我修正全部是内部执行过程。
在到达终态前不得产生任何用户可见文字，包括路由说明、`priceRules/brand/material` 取值、步骤清单、
工具调用计划或结果、规则分析、“开始执行”、“现在展示提案”、自我质疑或自我修正。

只允许以下两种终态可见回复：

1. **成功终态**：本轮校验成功且 `diffRecordId>0`，只输出第 4 节的完整 EDIT 提案模板。
2. **失败终态**：命中本文规定的终止条件，只输出该条件对应的最终错误文本。

进入终态时，必须先将可见回复缓冲视为空。成功时仅使用已锁定的
`agentNameOrId`、`basePromptName`、`selectedPromptVersionId`、用户原始要求、本轮实际依据、
`diffRecordId` 和 `diffContent` 重组第 4 节模板；任何过程草稿都必须丢弃，禁止保留在模板之前或之后。

## 1. 分支判定

**先锁定分支，一次请求只能锁定一个，后续工具响应不得改变已锁定分支：**

1. **精确修改直达分支**：用户给出可唯一定位的增删改（材质组、母子品牌、比价项、规则句、章节等）。
   基础正文结构可用时跳过规则查询，只执行指定局部变更及必要机械一致性调整。
   用户已定位现有章节、字段或规则句并给出追加、删除、替换内容时，按被修改的目标判定为精确修改；
   待写入内容中出现“母子品牌关系”“材质关系”等术语，不得据此改判为当前规则同步。
   若同时命中"格式重构硬分支"，则必须执行规则查询重构完整正文。

2. **当前规则同步分支**：用户要求"根据/按照/依据/基于/通过/同步当前或最新的比价项规则、母子品牌关系、
   材质关系更新提示词"或等价表达。
   触发判别：上述对象必须作为**数据来源/依据**出现，而非作为修改目标。来源词后只写“规则”且没有
   进一步限定时，按“当前比价项规则”处理并令 `priceRules=true`，例如“按照比价项规则改一下”“根据比价项规则
   优化”“同步一下比价项规则”。“根据母子品牌关系同步”“按最新材质关系更新”则只命中对应对象。
   “新增一个母子品牌”“删除这组品牌”“把某条比价项规则改成……”属于精确修改直达分支。
   本分支内部按用户明确指定的同步对象拆成三类，可单独命中，也可组合命中：
   - `priceRules=true`：用户明确提到"比价项规则""规则表""当前规则""最新规则"或等价表达；同步比价项、优先级、匹配逻辑、Step3 和输出结构。
   - `brand=true`：用户明确提到"母子品牌""品牌关系""品牌映射"或等价表达；按本轮真实品牌比价项
     同步品牌比价项及母子品牌映射。真实 `compareItem` 均不含"品牌"时，同步结果固定为删除基础正文中的
     品牌比价项及其所有结构落点、全部母子品牌内容，不得以"保持原样""未扩写""未新增"代替删除。
   - `material=true`：用户明确提到"材质关系""材质映射""材质对照表"或等价表达；按本轮真实材质比价项
     同步材质引用、材质对照表和材质抽取值格式规则。真实 `compareItem` 均不含"材质"时，同步结果固定为删除
     基础正文中的全部材质内容，不得以"保持原样""未扩写""未新增"代替删除。
   用户同时明确指定多个同步对象时，只处理这些对象的组合；未指定的对象不得顺手修改、查询关系或在提案中声称已同步。
   命中 `brand` 或 `material` 时仍必须先完整执行类目规则查询，用真实 compareItem 判断门禁并获取对应 `cateNameTree` 作用域。

3. **格式重构硬分支**：查询到的 `promptContent` 明显不符合格式规范（仅为数字、短句、占位内容，或缺少固定章节、真实比价项、完整输出约束）。
   必须执行规则查询并重构为符合格式规范的完整提示词。不得询问用户优化方向，不得保留残缺结构。

4. **无方向普通修改**：仅说"修改/优化提示词""修改/优化规则""规则改一下"等，既无具体改动，也未显式指定
   "依据当前规则/比价项规则/母子品牌关系/材质关系"作为同步依据。
   基础正文结构合规时必须跳过规则查询，只依据正文现有内容修复格式、歧义、重复、矛盾、术语、Step 和 JSON 约束；
   不加载比价项、品牌或材质关系，不启用全量同步门禁，不借机补写或改写业务规则。

> **判定看“规则”的语义角色，而不是只匹配关键词：**
> - **来源/依据**：“按照规则改一下”“根据当前规则优化”走分支 2，`priceRules=true`。
> - **具体修改目标**：“把品牌规则中的 A 改成 B”走分支 1。
> - **无来源、无具体内容**：“优化规则”“规则改一下”走分支 4。
>
> 用户明确说了哪几类同步对象，就只同步哪几类；同时说多类时才组合同步，未说到的对象保持原文。

> **"母子品牌"按完整业务词识别；不得将"母婴"类目误识别为母子品牌关系。**
> **残缺正文不是外部依赖错误**：`promptContent` 为 `1`、`111` 或其他残缺内容时，禁止声称"未找到配置"，
> 禁止要求用户补充骨架，必须执行格式重构硬分支。

## 2. 查询与判断

### 2.1 版本路由

沿用 `SKILL.md` 入口绑定的 `currentPromptVersionId`；不大于 0 时立即停止，回复路由错误（EDIT 流程要求 promptVersionId>0），不得在 EDIT 内部切换到 INITIALIZE 流程。

### 2.2 补充 ruleGroupId

- 已有 `ruleGroupId`：跳过。
- 缺失且 `agentId<=0` 或为占位符：立即停止，返回业务上下文参数错误。
- 缺失且 `agentId>0`：调用 `query_agent_detail(agentId=上下文.agentId, operator=上下文.operator)`；
  仅 `baseResp.respCode=1` 时读取 `data.card.ruleGroupId`，仍为空则停止。

### 2.3 基础版本查询

仅"当前提示词"允许执行精确查询。用户要求指定其他版本 ID、名称或切换版本时，只回复：
"当前操作仅使用本轮业务上下文中的提示词版本，不支持通过用户文字指定或切换版本。"

`tool_query_prompt_skeleton(ruleGroupId=上下文.ruleGroupId, promptVersionId=currentPromptVersionId, versionName="", queryOnline=false, queryLatest=false, operator=上下文.operator)`

仅当 `baseResp.respCode=1` 且 `data.data.promptVersion` 非空时检查版本状态和正文。正文固定读取
`data.data.promptVersion.promptContent`，正文的 `null`、空串或纯空白均视为空：

- `versionStatus` 为 1、2 或 3 且正文非空：允许作为只读基础派生新草稿；记录 `selectedPromptVersionId`，锁定 `writeMode=EDIT`。
- `versionStatus` 为 1、2 或 3 且正文为空：报告数据异常并停止，不得改走初始化。
- 其他 `versionStatus`：停止并报告未知状态。
- 响应版本 ID 不等于本轮 `currentPromptVersionId`：报告查询数据错误并停止。

> `versionStatus` 枚举：1=草稿（可修改）、2=线上（可作为只读基础派生草稿）、3=归档（可修改）

### 2.4 审计 promptContent

按 3.5 节格式模板完整审计本轮 `tool_query_prompt_skeleton` 响应中的
`data.data.promptVersion.promptContent` 字段。不得审计 `versionName`、`diffContent`、历史消息或模型记忆中的其他正文：
仅含数字、短句、占位内容，或缺任一固定主体章节（`# 角色`、`# 输入说明`、`# 执行步骤`、`# 判定规则`、`# 图片说明`、`# 输出格式`）、真实比价项和完整输出约束时，立即锁定"格式重构硬分支"；
不得等待用户补方向，不得把残缺原文直接提交校验。

### 3.0 直达/普通修改局部编辑规则

#### 3.0.1 精确修改直达局部编辑规则

本节只在精确修改直达分支执行。候选必须从 2.3 查询到的基础正文派生，禁止重建全文、禁止查询规则或关系、
禁止借机同步未请求的比价项、品牌、材质或货号规则。

1. **定位目标**：先在基础正文中定位用户明确指定的比价项、规则句、章节、母子品牌组、材质行或映射子表。
   只能编辑被明确定位的目标及其必要相邻结构；无法唯一定位时停止，回复需要用户明确修改对象。
2. **局部编辑范围**：
   - 修改比价项规则时，只改该比价项章节内对应的优先级、匹配、说明句或材质引用行；不得重写其他比价项、Step3 或输出格式。
   - 修改母子品牌时，只改 `### 母子品牌映射表` 中用户指定的母品牌组或子品牌成员；不得查询品牌关系库补齐。
   - 修改材质时，只改用户指定的材质引用行或材质对照表文本行；不得查询材质关系库补齐，不得改写未指定材质行。
   - 修改章节文字时，只改用户指定章节或句子；不得改名、调序、删除固定章节。
3. **机械一致性**：局部编辑后必须保持章节标题、JSON 字段规则、映射表格式、材质引用行与材质表对应关系、
   以及比价项章节和品牌映射编号连续；删除任一编号项后按 3.4 重新编号。
4. **禁止声称来源**：提案只能说明依据是"用户明确指定"；不得声称执行了当前规则同步、品牌关系查询、
   材质关系查询、比价项转换账本或格式重构。

#### 3.0.2 无方向普通修改整理规则

本节只在无方向普通修改分支执行。候选必须从 2.3 查询到的基础正文派生，禁止重建全文、禁止查询规则或关系、
禁止借机同步比价项、品牌、材质或货号规则。

1. **允许整理范围**：只允许修复基础正文中已经存在的格式、歧义、重复、矛盾、术语不统一、Step 表述不顺、
   JSON 约束不清或编号断号问题。
2. **禁止新增业务规则**：不得新增、删除或改写比价项；不得新增品牌互认、材质互认、货号例外、来源优先级、
   匹配逻辑、综合判定例外或类目适用范围。
3. **保持正文结构**：不得套用 3.5 候选提示词格式模板重建全文；基础正文已有固定章节时保持标题、顺序和主体内容。
   若只需补齐 JSON 字段规则或修复章节格式，只补齐缺失的固定格式约束，不改写业务规则含义。
4. **机械一致性**：整理后必须保持比价项章节和品牌映射编号连续、材质引用行与材质表互相一致、JSON 示例可解析。
5. **禁止声称来源**：提案只能说明依据是"基础正文整理"；不得声称执行了当前规则同步、品牌关系查询、
   材质关系查询、比价项转换账本或格式重构。

### 3.1 按需加载规则/关系结果

仅格式重构硬分支、当前规则同步分支才执行本节。
精确修改和结构合规的无方向普通修改**禁止**因"可能需要"而加载规则或关系。
当前规则同步分支只加载用户明确指定同步对象所需的数据：
- `priceRules=true`：只需要类目规则，不查询品牌关系或材质关系，除非用户同时明确指定 `brand=true` 或 `material=true`。
- `brand=true`：必须先查类目规则，用真实比价项判断是否允许品牌映射；作用域非空才查询品牌关系，
  作用域为空则不查关系，并删除基础正文中的全部母子品牌内容。
- `material=true`：必须先查类目规则，用真实比价项判断是否允许材质映射；作用域非空才查询材质关系，
  作用域为空则不查关系，并删除基础正文中的全部材质内容。
- 多个同步对象同时指定时合并加载，已加载的数据复用一次，不重复查询；未指定对象对应的关系接口禁止调用。

#### 3.1.1 类目规则查询

1. 调用 `tool_query_category_ids(ruleGroupId=上下文.ruleGroupId, agentId=上下文.agentId, operator=上下文.operator)`。
   要求 `baseResp.respCode=1` 且 `data.categoryIds` 非空；只使用该去重列表，禁止从历史或模型记忆补类目 ID。

2. 遍历全部 `data.categoryIds`，逐个调用 `radar_query_price_rule(categoryId=<当前 categoryId>)`；

   `data.baseRespInfo.respCode=1`、`data.labelCateRule.isExist=true`，且 `data.labelCateRule` 完整；
   任一 categoryId 不满足即停止，不得用其他类目的规则补齐。

3. 对每次 `radar_query_price_rule` 响应，读取 `data.labelCateRule` 并建立该 categoryId 的规则记录：
   作用域字段只取 `cateNameTree`；规则字段读取
   `ruleTableInfo.ruleTableInfo[]` 中的 `compareItem`、`infoSource`、`compareLogic`，
   以及同级的 `data.labelCateRule.specialRuleContent.ruleContent`。记录该 categoryId 下完整的 `compareItem` 列表，
   即"哪个 categoryId 有哪些比价项"；作用域和规则表非空才可继续。
   查询完成后，后续 3.1.2、3.2、3.5 只能使用本轮 categoryId 规则记录，
   不得重新从历史、基础正文或模型记忆补规则。

#### 3.1.2 统一作用域过滤

**共同来源约束**

品牌作用域和材质作用域只能由本轮各 categoryId 的
`ruleTableInfo.ruleTableInfo[].compareItem` 推导。禁止根据工具可用性、历史响应、基础正文、常识或
用户未绑定到真实比价项的数据反推作用域。常识只能用于删除不相关结果，不得用于新增、恢复、合并、
改名或补充别名。

**品牌作用域**

只收集 `compareItem` 精确等于"品牌"的 categoryId 对应 `cateNameTree`，去重后记为
`brandScopeCateNameTreeSet`。

若全部真实 `compareItem` 均不含"品牌"，立即锁定
`brandScopeCateNameTreeSet=空集`、`brandGroupCount=0`：
- 不得调用品牌关系工具，即使上下文中已有品牌响应也必须忽略；
- 格式重构硬分支或 `brand=true` 时，重建候选不得出现品牌比价项及其结构落点、母子品牌映射或映射引用；
- `brand=false` 表示本轮不更新品牌关系；即使品牌作用域为空，也不得删除或改写基础正文已有的母子品牌映射。

当前规则同步分支中，只有 `brand=true` 才允许进入 3.1.3；`brand=false` 时即使
`brandScopeCateNameTreeSet` 非空也不得查询品牌关系、不得改写母子品牌映射表。本节完成后，品牌流程
只使用本轮 `brandScopeCateNameTreeSet`。

**材质作用域**

对每个名称包含"材质"的真实 `compareItem` 建立一行 `materialScopeLedger`，每行固定记录
`(categoryId, cateNameTree, compareItem)` 并保留 `compareItem` 原名；再将账本中的
`cateNameTree` 去重投影为 `materialScopeCateNameTreeSet`。

若全部真实 `compareItem` 均不包含"材质"，立即锁定
`materialScopeLedger=空`、`materialScopeCateNameTreeSet=空集`、`materialOutputGroups=空`：
- 不得调用材质关系工具，即使上下文中已有材质响应也必须忽略；
- 格式重构硬分支或 `material=true` 时，重建候选不得出现材质引用、材质对照表或材质抽取值格式规则；
- `material=false` 表示本轮不更新材质关系；即使材质作用域为空，也不得删除或改写基础正文已有的材质引用行和材质对照表。

`materialScopeCateNameTreeSet` 后续只负责材质工具调用门禁；材质行的过滤、归属和输出分组必须使用
`materialScopeLedger`，不得退化为只按类目集合过滤。所有材质作用域仍输出在一张材质对照表内，
不得按类目复制整张表，也不得扩大成"电商全站"。

当前规则同步分支中，只有 `material=true` 才允许进入 3.1.4；`material=false` 时即使
`materialScopeCateNameTreeSet` 非空也不得查询材质关系、不得改写材质引用行或材质表。本节完成后，
材质调用门禁只使用本轮 `materialScopeCateNameTreeSet`，材质过滤和候选生成只使用本轮
`materialScopeLedger`。

#### 3.1.3 主子品牌关系查询

格式重构硬分支中，`brandScopeCateNameTreeSet` 非空时必须执行本节；为空时不得执行、不得调用工具、
不得输出母子品牌映射表及任何品牌映射说明。
当前规则同步分支中，仅当 `brand=true` 且
`brandScopeCateNameTreeSet` 非空时执行本节；`brand=true` 但集合为空时记录为"按真实比价项门禁不适用"，
不得调用工具，并必须从候选中删除基础正文已有的品牌比价项及其输入说明表行、图片说明项、JSON 示例字段，
以及母子品牌映射表、品牌章节中的映射引用和相邻的孤立分隔线；不得保留、扩写或新增任何品牌专属内容。
品牌映射只使用 `brandScopeCateNameTreeSet` 统一过滤母子品牌；不得使用其他 categoryId 的类目，
也不得把品牌范围扩大到全站或其他类目。

调用 `radar_query_brand_relation`；全量查询传 `keyword=""`；
不得自行添加 `cateName`、`categoryId` 或其他未定义参数。

成功条件：`result=1`、`error_msg` 为空、`data.baseResp.respCode=1`，且 `data.groups` 可解析。

读取：`groups[].mainBrand.id/brandName/isMainBrand/parentId`、`groups[].subBrands[].id/brandName/isMainBrand/parentId`、`groups[].subCount`。

每组必须满足：主品牌名称非空、`mainBrand.isMainBrand=true`、`mainBrand.parentId=0`；
至少一个子品牌，且每个子品牌名称非空、`isMainBrand=false`、`parentId=mainBrand.id`；
`subCount` 必须等于有效 `subBrands` 数量。不满足的整组删除。

过滤顺序（硬约束）：
1. 先遍历并校验 `data.groups` 全部组，不得预先截取前 N 组；
2. 再按 `brandScopeCateNameTreeSet` 对全部有效组做一次统一相关性过滤。过滤只看 `mainBrand.brandName`，不看子品牌名称；只有能够明确指出该母品牌直接属于集合中某个真实 `cateNameTree` 时才保留，无法确认、仅可能相关或跨行业时一律删除。不得因为子品牌相关、品牌知名、属于消费品或关系库返回了该组而保留。
3. 为每个保留组建立内部品牌保留账本，逐组记录 `mainBrand.id`、`mainBrand.brandName`、命中的真实 `cateNameTree` 和全部有效 `subBrands`。每组必须至少命中一个真实 `cateNameTree`；不能写出命中类目的组不得进入账本。例如作用域含酒类时可保留茅台、五粮液、泸州老窖、张裕、嘉士伯等明确酒类母品牌，必须删除小米、联想、OPPO、长城汽车、吉利等其他行业母品牌。
4. 按 `mainBrand.id` 或 `mainBrand.brandName` 去重后，才对过滤结果应用 100 组上限；
5. 同一母品牌组不得因为命中多个 `cateNameTree` 重复输出；过滤后不足上限就只输出实际命中组，不得从已删除组回填或用常识补齐。

过滤后 0 组时，静默省略母子品牌映射表，不得输出空结果说明，也不得停止。
进入下一步前记录 `brandGroupCount = min(品牌保留账本组数, 100)`。母子品牌映射表必须逐组来自该账本，
输出组数必须精确等于 `brandGroupCount`，不得新增账本之外的母品牌，也不得遗漏账本中的有效子品牌。
过滤结果直接用于生成母子品牌映射表。
禁止添加"及相关品牌""全站常见品牌"等扩大作用域的措辞。**100 组是上限，不是生成目标**。
若恰好输出 100 组，必须重新逐组核对账本中的命中类目；任一组无法明确写出命中的真实 `cateNameTree`
就删除，禁止为凑满 100 组保留。

用户明确指定某组的新增、删除、替换或成员调整属于精确修改，直接执行用户指令，不查询关系库复核。

#### 3.1.4 同款材质关系查询

格式重构硬分支中，`materialScopeCateNameTreeSet` 非空时必须执行本节；为空时不得执行、不得调用工具、
不得输出材质表及任何材质说明。
当前规则同步分支中，仅当 `material=true` 且
`materialScopeCateNameTreeSet` 非空时执行本节；`material=true` 但集合为空时记录为"按真实比价项门禁不适用"，
不得调用工具，并必须从候选中删除基础正文已有的材质比价项、材质引用行、材质对照表、相邻的孤立分隔线
及材质抽取值格式规则；不得保留、扩写或新增任何材质内容。
`materialScopeCateNameTreeSet` 只用于本节调用门禁；材质映射必须使用 `materialScopeLedger` 中真实
`(categoryId, cateNameTree, compareItem)` 联合过滤，不得使用其他 categoryId、其他比价项或扩大到全站。

调用：`query_material_leaf(operator=上下文.operator)`

成功条件：`result=1` 且 `data.baseResp.respCode=1`。

读取 `data.materialText[]`：每项已是服务端稳定渲染的材质组文本行，格式为
`<完整路径（用·分隔）>：<叶子材质1>、<叶子材质2>...`，例如 `贵金属·金·足金：999金、纯金、黄金`。

模型无需自行解析服务端材质树结构，但必须读取当前 `materialText` 原文表达的材质组，并将它与账本行的
`cateNameTree + compareItem` 联合判断。这里的“命中”仅指：当前材质组能够明确归属于该类目下该材质维度；
不是判断两个字段是否存在字面包含关系。`cateNameTree`、`compareItem` 或当前原文中出现“材质”二字，
均不能单独构成命中。例如不得因为 `compareItem=材质` 就判定该类目命中全部材质原文，也不得声称
“`箱包/饰品` 包含 `材质`”。

`query_material_leaf` 是全量关系查询；接口返回某条原文，只能证明该原文存在，不能证明它命中任一
`materialScopeLedger` 账本行。基础正文已有的材质表、已有 `#### 适用范围` 总标题、接口返回条数，
也都不是本轮命中证据。无法根据“当前原文 + 当前账本行的 `cateNameTree + compareItem`”明确建立归属时，
该账本行固定判为不命中；禁止把不确定改判为全部作用域命中。

直接建立唯一结果对象 `materialOutputGroups = Map<适用范围标题, 原始材质行列表>`，这是材质映射的唯一中间结果。
禁止建立或输出“材质 × 作用域”的笛卡尔积明细、`materialRetentionLedger`、`materialScopeRunCount`
或二次汇总表。**80 条是完成作用域过滤和原文去重后的最终保留上限，不是接口返回条数，也不是过滤前
截取数量。** 不得先取 `materialText[]` 前 80 条再过滤；作用域有多个时也不得复制原文形成候选行。
1. 按接口顺序遍历 `materialText[]`。对当前原文逐行判断 `materialScopeLedger`：只使用当前账本行的
   `cateNameTree` 和 `compareItem` 判断是否命中，并收集所有明确命中的账本行；`材质`、`主材质`、
   `配件材质`、`表带材质`、`表壳材质`等不同 `compareItem` 均按独立作用域判断，不得折叠，不得因为
   它们都包含“材质”就同时命中。
2. 当前原文没有命中任何作用域时直接删除；不得根据材质名称凭常识猜测表带、表壳、配件等用途，
   不得用其他原文的判断结果补充当前原文的作用域。
3. 将命中的作用域按 `materialScopeLedger` 顺序排列，每项写成
   `<cateNameTree>｜<compareItem>`，用 `；` 连接成完整标题，并直接以该标题作为
   `materialOutputGroups` 的 key。
4. 当前原文通过作用域过滤后再去重；同一原文即使命中多个作用域，也只保留为一条并归入第 3 步生成的
   唯一组合 key。仅命中且去重后的原文计入 80 条上限，未命中行和重复行不占名额；按接口顺序只保留
   前 80 条合格原文。key 按首次出现顺序排列，各 value 内的原文保持接口顺序。过滤后不足 80 条就只
   保留实际条数，不得回填已删除行；达到 80 条也不得声称接口仅返回 80 条或所有原文均命中。

以 `materialOutputGroups` 直接渲染材质表：
- 结果为空时，静默省略材质引用和材质表，不输出空结果说明，也不得停止；
- 结果非空时，每个 key 只输出一次 `#### 适用范围：<key>`，随后连续输出其 value 中的全部
  `materialText`；
- 每条材质行以第一个全角冒号 `：` 为边界，只在冒号前的路径原文两侧添加 `**`，固定输出为
  `**<冒号前原文>**：<冒号后原文>`；除此之外，路径、冒号、成员名称及字符顺序必须与原始
  `materialText` 逐字符一致；
- `#### 适用范围` 只是归属元数据；每条原始 `materialText` 才是独立互匹配组，同一标题下的不同行
  不得互相匹配。

正确结构示例：
```markdown
#### 适用范围：类目A｜主材质；类目A｜配件材质
**天然宝玉石·和田玉**：碧玉、白玉
**天然宝玉石·琥珀**：血珀、蓝珀
**天然宝玉石·珍珠**：淡水珍珠、海水珍珠
#### 适用范围：类目B｜表壳材质；类目B｜表带材质
**贵金属·金·足金**：999金、纯金、黄金
**贵金属·金·18K金**：Au750、750黄金
```

例如账本同时包含 `(手表/钟表, 表带材质)`、`(手表/钟表, 表壳材质)`、`(珠宝, 材质)` 时，
对应标签分别写 `手表/钟表｜表带材质`、`手表/钟表｜表壳材质`、`珠宝｜材质`；若同一原文命中前两项，
该组标题写 `#### 适用范围：手表/钟表｜表带材质；手表/钟表｜表壳材质`。

本轮查询成功但 `data.materialText[]` 为空或 `materialOutputGroups` 为空时，
`materialOutputGroups=空` 只表示本轮没有可用的材质映射，不代表类目没有材质比价项。
当前规则同步分支 `material=true` 不能“保持基础正文原样”：候选必须删除基础正文已有的全部材质对照表、
所有 `- **材质对照表**` 引用行及删除后孤立的分隔线；本轮真实 `compareItem` 仍包含“材质”时，
必须保留材质比价项及材质抽取值格式规则。

### 3.2 比价项转换账本（当前规则同步 + 格式重构硬分支）

内部转换账本按"每个类目下的每个比价项"分别记录，用 `categoryId` 区分不同类目记录。同名 `compareItem` 出现在多个 categoryId 下时，
必须分别用各自类目记录中的 `cateNameTree`、`infoSource`、`data.labelCateRule.specialRuleContent.ruleContent` 和
`compareLogic` 推导一行账本。

为每个真实类目记录下的每个 `compareItem` 生成内部转换账本，每行记录：

| 字段 | 说明 |
|---|---|
| `categoryId` | 当前规则所属类目 ID |
| `cateNameTree` | 当前规则所属类目路径原文，例如 `美妆/彩妆` |
| `compareItem` | 真实名称 |
| `infoSource` 原文 | 当前 categoryId 下的原始字段 |
| `expectedPriority` | 按当前 categoryId 的来源过滤规则推导；生成提示词时必须与此完全一致 |
| 清洗后特殊规则 | 删除 SKU 后的当前 categoryId 下 `data.labelCateRule.specialRuleContent.ruleContent` 对应内容 |
| `compareLogic` 原文 | 当前 categoryId 下的原始字段 |
| 别名归一后标准 `compareLogic` | 见下方枚举 |
| `expectedMatch` | 清洗后特殊规则 + 兜底规则；生成提示词时必须与此完全一致 |

**账本完整性**

- 任一账本字段推导失败时，禁止继续生成。
- 当前规则同步分支 `priceRules=true` 时，账本必须覆盖每个真实 categoryId 下的每个
  `ruleTableInfo[]`。每条账本行都必须有候选落点，且候选优先级与 `expectedPriority` 完全一致、
  候选匹配与 `expectedMatch` 完全一致；全部满足才算完成比价规则覆盖。

**比价项全集**

- 账本完成后立即锁定 `validCompareItemSet`：取本轮全部 categoryId 的
  `ruleTableInfo.ruleTableInfo[].compareItem`，按首次出现顺序去重。
- 当前规则同步或格式重构硬分支重建 `# 输入说明` 表、`## 比价项` 章节和 JSON 示例 `extracted`
  业务键时，三处都必须完整覆盖 `validCompareItemSet`。
- 不得因为比价项只属于部分类目、输入样例的 `category` 未命中、其他类目没有该项、篇幅压缩或模板
  只展示两行示例而删除。真实规则中的 `品种`、`产地` 等普通比价项也必须进入全集，并只在其真实
  适用类目下生效。

**`priceRules=false` 分支边界**

- 不建立比价项转换账本，不重建完整比价项章节、Step3 或输出结构。
- `brand=true` 时，只允许改写或删除品牌比价项及其结构落点、母子品牌映射表、品牌章节中的映射引用
  及其相邻的必要结构；`brand=false` 时，品牌相关内容保持基础正文原样。
- `material=true` 时，只允许改写或删除材质比价项、材质引用行、材质对照表、材质抽取值格式规则
  及其相邻的必要结构；`material=false` 时，材质相关内容保持基础正文原样。

#### 3.2.1 来源过滤（生成 expectedPriority）

1. 必须读取完整 `infoSource` 的全部行，不得只读取首行。先按换行从上到下拆行，再在每行内从左到右扫描，
   将 `>`、`/`、`=` 都视为来源边界，拆成最小片段；各行投影结果按原始行序依次合并。
2. 任一片段只要包含大小写不敏感的连续字样 `sku`，该片段直接删除（即使同时含白名单词）。
3. 对剩余片段做白名单包含匹配并替换为标准词：
   - 含 `商品属性`（包括`商品属性栏`、`属性栏`等）→ `商品属性`；
   - 含 `商品标题` → `商品标题`；
   - 含 `主图`（包括`主图文字说明`、`主图中的文字描述`、`主图文字描述`等）→ `主图`；
   - 其他删除。
   映射后 `expectedPriority` 只能由 `商品属性`、`商品标题`、`主图` 三个标准词组成，禁止保留
   `主图文字说明`、`主图中的文字描述`、`商品属性栏` 等原始来源措辞。
4. 保留原序（首次出现）去重，用 `>` 连接。过滤后无任何合法来源时，固定写
   `综合判断（商品标题/商品属性/主图同等参考）`。
5. 这是删除与归一化投影，不是重新判断优先级：候选来源的数量、内容和相对顺序必须逐项等于投影结果，
   不得交换、补充或按模型偏好重排。例如 `比价维度>sku图>商品标题>主图>商品属性`
   必须投影为 `商品标题>主图>商品属性`，不得写成 `主图>商品标题`。

#### 3.2.2 compareLogic 枚举（单一事实源）

先去除输入首尾空白，再按以下受控别名精确归一；命中受控别名时，必须用对应标准匹配语义全文替换别名。
`expectedMatch` 和候选的 `匹配` 行不得保留或添加别名名称及冒号，例如禁止输出
`通用匹配逻辑：左右两侧...`。不得只输出逻辑名称，不得自行补充阈值、默认值或行业判断。

**受控别名**：
- `通用匹配逻辑`：左右两侧该比价项一致，或者信息不冲突，或者存在交集，即可匹配。
- `优先完美匹配逻辑`：左右两侧该比价项一致或信息不冲突即可匹配。
- `影响价格匹配逻辑`：左右两侧该比价项一致或信息不冲突即可匹配。
- `严格匹配逻辑`：左侧有该比价项时，右侧必须有且一致才可匹配；左侧有、右侧无时不可匹配；
  左侧无、右侧有时可匹配。
- `货号匹配逻辑`：
  - 货号不一致/缺失→**禁止**仅凭货号判different，必须继续看其他项
  - 可忽略符号，去符号后一致即匹配
  - **除货号外其他项均match=true→必须判same**（货号不一致不构成否决）

按类目记录分别判断是否使用货号 Step3：收集 `compareLogic=货号匹配逻辑` 的 categoryId 对应
`cateNameTree` 集合，记为 `partNoStep3CateNameTreeSet`；其余 categoryId 对应 `cateNameTree` 集合记为
`normalStep3CateNameTreeSet`。`partNoStep3CateNameTreeSet` 非空时，必须为该集合生成以下完整综合判定；
`normalStep3CateNameTreeSet` 非空时，仍保留普通 Step3。两个集合都非空时，按适用类目分成两个 Step3 小节，
小节标题中用逗号拼接对应 `cateNameTree` 原文；若只有一个集合非空，则只输出一个 Step3，标题固定为
`**Step3：综合判定**`，判断只认 `compareLogic`。
生成时将下方普通 Step3 和/或货号 Step3 直接填充到 3.5 完整格式模板的 Step3 指定位置。
当前规则同步分支只有 `priceRules=true` 时才允许按本节重建货号相关规则和 Step3；`priceRules=false`
且只同步品牌/材质时不得改写货号规则、Step3 或输出结构。

```markdown
**Step3：综合判定<仅当 partNoStep3CateNameTreeSet 也非空时追加：（适用于：<normalStep3CateNameTreeSet 中的 cateNameTree 原文，多个用逗号分隔>）>**
—基于所有生效比价项的`match`字段得出`result`：
- 所有生效比价项`match=true`时，必须判定为`same`。
- 任一生效比价项`match=false`时，必须判定为`different`。
- 严禁跳过Step1、Step2直接给出`result`；必须先完成抽取和逐项匹配，再得出最终结论。

**Step3：综合判定<仅当 normalStep3CateNameTreeSet 也非空时追加：（适用于：<partNoStep3CateNameTreeSet 中的 cateNameTree 原文，多个用逗号分隔>）>**
—基于所有生效比价项的`match`字段得出`result`：
- 先排除当前类目下 `compareLogic=货号匹配逻辑` 的生效比价项，仅聚合其他生效比价项。
- 其他生效比价项全部`match=true`时，必须判定为`same`。
- 其他生效比价项任一`match=false`时，必须判定为`different`。
- 被排除项不一致、缺失或`match=false`绝对不构成否决，不得作为判定`different`的理由。
- 严禁跳过Step1、Step2直接给出`result`；必须先完成抽取和逐项匹配，再得出最终结论。
```

其他非空且未命中标准枚举或受控别名的 `compareLogic`：只保留真实原文，不解释、不近似映射。
空值或去除首尾空白后为 `""`、`"-"`、`"—"` 时，不生成兜底语义。


#### 3.2.3 匹配内容规则（生成 expectedMatch）

`data.labelCateRule.specialRuleContent.ruleContent` 可能存在多种原始格式：以 `$序号. 比价项名称：` 为段标题开始、`$` 为段标题结束，后接换行和段内容；若已去掉 `$` 符号，则以 `序号. 比价项名称：` 行为段起始、下一个 `序号+1.` 行为段结束；也可能是 `比价项名称` 独占一行，下一行开始写该比价项解释，直到下一个比价项名称行、下一个序号标题或文本结束；也可能是一整段自然语言说明，没有明显段标题。

每项"匹配"只能按以下顺序组成：
1. 解析当前 categoryId 下的 `data.labelCateRule.specialRuleContent.ruleContent`：按上述分段规则过滤全文，找到归属于当前 `compareItem` 的内容块；
   若原文是一整段自然语言说明且无法按标题分段，则自行筛选其中与当前 `compareItem` 直接相关的句子或片段；
   取标题行冒号后的内容、独占比价项名称行之后的解释，以及后续正文作为该比价项的专属规则原文；
   只把关于当前比价项的内容放入该比价项"匹配"中，无对应内容块时此步骤结果为空。
   删除原文中所有 SKU 来源、SKU 图片、SKU 标题、SKU 包装等内容；混合句删除后语义不完整时整句删除，
   禁止把 SKU 改写为主图、商品标题或商品属性。
2. 处理该项真实 `compareLogic`：先取当前 categoryId 下当前 `compareItem` 对应的 `compareLogic` 原文；
   若命中上方受控别名，则追加该别名对应的标准匹配语义原文，例如"左右两侧该比价项一致，或者信息不冲突，即可匹配。"；
   若 `compareLogic` 不是上方任何受控别名，但接口返回了非空原文，则直接追加这段原文；
   若接口未返回 `compareLogic` 或内容为空，则不追加匹配逻辑。

无法唯一归属某个比价项但影响多项的特殊规则写入"总原则"，不得新建比价项。
禁止根据比价项名称、旧提示词或模型常识补写规则。

  时候选中不得出现母子品牌映射表或空结果说明。

#### 3.3.2 材质

  `- **材质对照表**：见下方附录。`，并在 `## 映射表` 中输出
  `### 材质对照表（每条材质行内可互匹配，不同行不可）`；`materialOutputGroups` 为空时两处都不得出现。
- 当前规则同步分支 `material=true && materialScopeCateNameTreeSet=空集` 时是删除同步：即使基础正文已有材质内容，也必须
  删除材质比价项、材质引用行、材质对照表、材质抽取值格式规则及删除后多余的分隔线；若映射表只剩母子品牌，
  保留 `## 映射表` 和母子品牌子表，删除两个子表之间原有的 `---`。

  删除基础正文已有的全部材质引用行和材质对照表；若 `## 映射表` 只剩该材质表则删除整个章节，若仍有
  母子品牌表则保留母子品牌表并删除两个子表之间的孤立 `---`。真实材质比价项、其规则和材质抽取值格式规则保留。
- 材质引用行不属于"匹配"，不得缩进到"匹配"子项中，不得计入 `expectedMatch`。
- 实际执行时只能使用与当前输入 `category` 和当前材质 `compareItem` 共同命中的适用范围分组，

  `material=true && materialScopeCateNameTreeSet=空集` 规则执行删除同步。
- 当前规则同步分支只要 `material=false` 就必须保持基础正文中的材质引用行和材质对照表；仅同步比价规则
  （`priceRules=true && material=false`）时也不得按本轮材质作用域删除或重建。
- 格式重构硬分支必须按本轮真实材质作用域重建；作用域为空时删除旧材质内容，作用域非空时按
  `materialOutputGroups` 输出或省略材质映射。

### 3.4 映射与比价项编号规则

#### 3.4.1 品牌映射格式与编号

每组格式固定为 `序号. 母品牌→子品牌1|子品牌2`，每个主品牌组独占一行。
过滤或删除任一组后，必须重新编号：删除第 K 个品牌组时，原第 K+1 个品牌组自动改成第 K 个，
原第 K+2 个品牌组自动改成第 K+1 个，直到最后一组。最终品牌组编号必须是 `1、2、3...N`
连续递增，不得保留断号、重复号、跳号或旧编号。
过滤结果为 0 组时静默省略品牌映射表。

#### 3.4.2 比价项章节格式与编号

每个比价项章节标题格式固定为 `### 序号. 比价项名称`，每个真实 `compareItem` 独占一个章节。
标题只写 `compareItem` 原名，禁止追加 `（仅<类目>生效）`、`（适用于：<类目>）`、类目列表或其他作用域说明；
适用类目只由 `# 输入说明` 表表达。
生成骨架时必须覆盖所有 categoryId 全量规则中按 `compareItem` 名称去重后的比价项并集；禁止按任一输入样例的 `category` 裁剪比价项章节。
同一 `compareItem` 出现在多个 categoryId 下时，内部账本保留多条 `(categoryId, compareItem)` 记录，
但提示词正文只生成一个同名比价项章节，并在 `# 输入说明` 表的同一行合并列出全部适用类目。
只有真实规则全集变化、去重合并同名
`compareItem` 或用户明确删除真实规则项时才允许删除或合并章节。删除第 K 个章节时，原第 K+1 个章节
自动改成第 K 个，原第 K+2 个章节自动改成第 K+1 个，直到最后一项。最终章节编号必须是 `1、2、3...N`
连续递增，不得保留断号、重复号、跳号或旧编号。

### 3.5 候选提示词格式模板（当前规则同步 + 格式重构硬分支）

以下模板是生成候选提示词的直接依据。所有尖括号内容必须替换为本轮真实数据；条件不适用时删除
对应行，不得留下占位符、`TODO` 或空标题。
当前规则同步或格式重构硬分支一旦锁定，候选构建方式也必须同时锁定为
`INSTANTIATE_EDIT_4_5_TEMPLATE`：先将下方外层围栏内从 `# 角色` 到 `# 输出格式` 的完整模板复制为内部候选基底，
再仅执行占位符替换、条件行删除、真实比价项展开和映射表插入；禁止从空白文本自由组织候选结构。
候选的第一个字符必须是模板内 `# 角色` 的 `#`，最后一个字符必须属于固定 `# 输出格式` 块的最后一行；
禁止在模板之前或之后拼接自定义草稿、格式说明或推理文字。
禁止根据校验工具 `errors`、旧 Prompt、历史候选或通用 Prompt 知识反推、补写或仿造格式；
校验失败只能在该模板实例中按 `data.errors` 修正对应真实内容，不得切换为自定义结构。
禁止生成“精简但完整”“大致结构”“代表性材质”、省略号、`...`、`同上`、`选取相关`或任何占位式候选；
数量只能按真实过滤账本和上限规则确定，不得为节省 token 自行抽样。
**禁止将本节的规范说明句子复制、改写或解释后写入 `promptContent`**；只有模板围栏内从 `# 角色` 至
`# 输出格式`（含 7 条通用字段规则，以及真实比价项包含材质时的 1 条条件字段规则）的内容才是正文结构。

**输入说明表生成规则**（仅用于生成，不得写入 `promptContent`）：遍历 `validCompareItemSet` 中全部
`compareItem`，以比价项名称为行；同名 `compareItem` 出现在多个 categoryId 下时合并到同一行，
各 `cateNameTree` 原文用逗号拼接；只出现在部分 categoryId 下的只填那几个 categoryId 的
`cateNameTree`，不得把无关类目填进来；同名 `compareItem` 不出现重复行；`cateNameTree`
已代表该路径下的全部子类目。表格行数必须等于 `validCompareItemSet` 大小；模板中的两条示例行不是上限。

**比价项章节生成规则**（仅用于生成，不得写入 `promptContent`）：生成 `## 比价项` 前，必须先按
`compareItem` 对 3.2 内部转换账本分组；每个 `compareItem` 分组只实例化一次下方
`### 序号. <比价项名称>` 模板，不得按 `categoryId` 或账本行数重复生成章节。下方"情况一/情况二"
只决定同一个比价项章节内部的 `优先级`、`匹配` 字段写法，不代表生成多个同名章节。
生成阶段必须遍历完整 `validCompareItemSet`；`activeCompareItemSet` 只允许出现在最终 Prompt 的运行时规则中，
不得用于裁剪 `# 输入说明` 表、`## 比价项` 章节或 JSON 示例业务键。
按以下三种情况确定字段格式：
填充每个 `匹配` 占位时，只能直接复制对应账本行的 `expectedMatch`；禁止根据 `compareLogic` 名称再次解释、改写或另行生成匹配文案。
1. 该比价项只属于一个 categoryId：输出无类目后缀的 `优先级` 和 `匹配`。
2. 该比价项属于多个 categoryId，且组内所有 `expectedPriority` 和 `expectedMatch` 均逐字符一致：

     则必须已逐项证明所有比价项规则完全一致，否则禁止形成提案。
   - 任一项不满足都不得调用校验，不得形成只修改映射表的不完整提案。
9. 精确修改直达分支若涉及映射表，只执行用户指定局部变更及必要机械一致性校验：
   不调用关系 MCP，不要求 `brandScopeCateNameTreeSet` 或 `materialScopeCateNameTreeSet`；
   但仍必须保持映射格式、数量上限、非空标题、连续编号、材质引用行与材质表互相一致。任一条件不满足禁止调用校验。

### 3.7 硬门禁

1. **来源投影门禁**：每个 `compareItem` 的 `expectedPriority` 必须通过来源过滤规则推导，不得省略、
   重排或补入原文不存在的来源；`商品属性栏（站外）` 必须归一为 `商品属性`；所有包含`主图`的合法片段
   必须归一为 `主图`，候选优先级不得残留`主图文字说明`、`主图中的文字描述`、`主图文字描述`等原始措辞；
   过滤后来源顺序和合法来源集合完全由算法决定，不得凭印象写固定值；
   `比价维度>sku图>商品标题>主图>商品属性` 必须逐字符投影为 `商品标题>主图>商品属性`。
2. **关系响应门禁**：品牌、材质正文只能来自本轮真实关系接口响应及过滤结果；
   母子品牌映射表只能逐组复制品牌保留账本，组数必须精确等于 `brandGroupCount`，每组必须有明确命中的真实
   `cateNameTree`；材质必须逐条复制 `materialOutputGroups` 中的本轮 `data.materialText[]` 原文，
   只允许在第一个 `：` 前的路径两侧新增 `**`，不得修改或补充其他字符，且只能用账本中真实
   `(categoryId, cateNameTree, compareItem)` 生成适用范围标题。
3. **候选泄漏门禁**：候选全文不得出现任何生成器门控、条件输出或内部算法说明，
   也禁止用"无符合""未命中""暂无"等空结果正文占位；不得出现 `<真实比价项>` 或任意尖括号占位符。
4. **归一化合并门禁**：同名比价项跨类目仅比较归一化后的 `expectedPriority` 和 `expectedMatch`；
   两者均逐字符一致时，候选只能有一组无类目后缀的 `优先级`、`匹配`，不得按类目重复。
   任一字段不一致时，候选必须为该比价项涉及的每个 `cateNameTree` 成对输出
   `优先级（<cateNameTree>）`、`匹配（<cateNameTree>）`，即使其中一个字段在各类目下相同也不得单独合并；
   出现“统一优先级 + 分类目匹配”或“分类目优先级 + 统一匹配”时禁止调用校验或形成提案。
   仅属于一个类目的比价项同样只能使用无类目后缀的 `优先级`、`匹配`。所有比价项章节标题只能是
   `### 序号. 比价项名称`，不得包含`仅...生效`、`适用于`或任何类目后缀。
5. **比价项全集门禁**：执行 `priceRules=true` 或格式重构硬分支时，`validCompareItemSet` 必须逐项来自本轮真实规则响应；
   候选中的输入说明表行、比价项章节和 JSON 示例业务键必须与该集合逐项一致。真实规则存在而候选遗漏的任一比价项，
   包括只在部分类目生效的 `品种`、`产地` 等普通比价项，均视为业务规则缺失，禁止调用校验或形成提案。
6. **品牌零作用域门禁**：执行 `brand=true` 或格式重构硬分支时，若真实 `compareItem` 均不含"品牌"，
   必须同时满足 `brandScopeCateNameTreeSet=空集`、`brandGroupCount=0`、无品牌工具调用，且重建后的候选
   不含品牌比价项及其输入说明表行、图片说明项、JSON 示例字段、母子品牌映射表、品牌章节中的映射引用、
   孤立分隔线或任何品牌专属说明；基础正文原有品牌内容必须删除，任一不满足均禁止调用校验。
7. **材质零作用域门禁**：执行 `material=true` 或格式重构硬分支时，若真实 `compareItem` 均不含"材质"，
   必须同时满足 `materialScopeLedger=空`、`materialScopeCateNameTreeSet=空集`、`materialOutputGroups=空`、无材质工具调用，且重建后的候选
   不含材质比价项、材质引用、`材质对照表`、`材质value`、孤立分隔线或任何材质专属说明；
   基础正文原有材质内容必须删除，任一不满足均禁止调用校验。

### 3.8 调用校验

`tool_validate_prompt_skeleton(promptContent=<候选全文>, operator=上下文.operator, conversationId=上下文.localConversationId, basePromptVersionId=selectedPromptVersionId, ruleGroupId=上下文.ruleGroupId, agentId=上下文.agentId)`

`ruleGroupId`、`agentId` 至少一个大于 0；`basePromptVersionId` 使用 2.3 节记录的 `selectedPromptVersionId`。

- `baseResp.respCode=1 && data.valid=true && data.diffRecordId>0`：成功，锁定本次 `promptContent`，保留 `diffRecordId`、`diffContent`。
  `data.diffContent` 在 EDIT 中不允许为空。
- `baseResp.respCode=1 && data.valid=true && data.diffRecordId<=0`：立即异常结束，回复
  "提示词校验未生成有效修改建议（diffRecordId=0），无法形成提案。"禁止重试。
- `data.valid=false`：只按 `data.errors` 修正报错处，其他正文不变，最多重试 2 次。
- 其他情况或重试后仍失败：只返回最终错误，不展示提案、不写入。

Diff 只取服务端 `data.diffContent`，禁止自行书写。
