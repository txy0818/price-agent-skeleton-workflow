# 枚举与魔法值对照表

本文件集中定义 workflow 使用的固定枚举和魔法值，是这些定义的唯一事实源。实际字段取值仍以本轮
MCP 返回为准；未命中本文件已定义枚举的真实值不得由模型猜测。

## 比价项匹配逻辑 `compareLogic`

本节是五种标准 `compareLogic` 及其受控别名的唯一事实源。其他 reference 只能引用本节，不得复制、
缩写、改写或只列其中一部分。先去除输入首尾空白，再按下方“受控别名”精确归一；随后展开标准
枚举，并将“该比价项”自然替换为真实 `compareItem` 名称，使句子可直接执行。不得只输出逻辑名称，
也不得自行补充阈值、默认值和行业判断。

### 受控别名

- `通用匹配逻辑`：左右两侧该比价项一致，或者信息不冲突，或者存在交集，即可匹配。
- `优先完美匹配逻辑`：左右两侧该比价项一致或信息不冲突即可匹配；优先匹配比价项一致的竞品，
  没有一致竞品时，才可匹配信息不冲突的竞品。
- `影响价格匹配逻辑`：左右两侧该比价项一致或信息不冲突即可匹配；优先匹配比价项一致的竞品；
  没有一致竞品时，判断该比价项差异是否影响价格，不影响价格才可匹配。
- `严格匹配逻辑`：左侧有该比价项时，右侧必须有且一致才可匹配；左侧有、右侧无时不可匹配；
  左侧无、右侧有时可匹配。
- `货号匹配逻辑`：货号不一致或缺失时，禁止仅凭货号判 `different`，必须继续判断其他生效比价项；
  可忽略符号，去除符号后一致即可匹配；除货号外其他生效比价项均 `match=true` 时必须判 `same`，
  货号不一致不构成否决。

当且仅当本轮某项真实 `compareLogic=货号匹配逻辑` 时，还必须把“货号不一致不构成否决，除货号
外其他生效比价项均匹配则判 `same`”同步写入 Step3 综合判定，避免通用“任一 false 即 different”
与该兜底冲突；不得仅因 `compareItem` 名称是“货号”就添加此例外。

其他非空且未命中标准枚举或受控别名的 `compareLogic` 属于未定义名称，只保留真实原文，不解释、
不近似映射到上述五种。空值或
去除首尾空白后为`""`、`"-"`、`"—"`时，不生成兜底语义。

## 提示词版本状态 `version_status`

| 值 | 含义 | 可否修改 |
|---:|---|---|
| 1 | 草稿 | 可以 |
| 2 | 线上 | 不可以 |
| 3 | 归档 | 可以 |


## 验证任务状态 `task_status`

| 值 | 含义 | 结果是否可读 |
|---:|---|---|
| 1 | 待执行 | 不能 |
| 2 | 执行中 | 不能 |
| 3 | 成功 | 可以 |
| 4 | 失败 | 不能 |
| 5 | 取消 | 不能 |

只有 `task_status=3` 时才可读取验证结果。

## 提示词来源 `source_type`

| 值 | 含义 |
|---:|---|
| 1 | 系统生成 |
| 2 | 模型优化 |
| 3 | 系统初始化 |

初始化写入使用 `source_type=3`，修改写入使用 `source_type=2`。

## 通用返回码 `base_resp.resp_code`

| 值 | 含义 | 处理 |
|---:|---|---|
| 1 | 成功 | 继续读取 `data` |
| 其他 | 失败 | 按 [SKILL.md](../SKILL.md) 的失败与重试规则处理，并向用户说明 `resp_desc` |

`resp_code=1` 只表示调用成功，不表示 `data` 内容完整。各流程仍需按自身要求校验关键字段非空。

## 线上版本查询开关 `query_online`

| 值 | 含义 |
|---:|---|
| false | 按 `prompt_version_id` 或 `version_name` 精确查询 |
| true | 查询当前线上版本，忽略 ID 与名称 |

本 Skill 的初始化和修改流程固定传 `false`。这只表示不使用“自动查询当前线上版本”的模式；
当业务上下文 `promptVersionId` 精确指向线上版本时，仍可按 ID 查询并将其作为只读基础派生新草稿。
`version_name` 不得取自用户消息；用户指定具体版本名称时应按 SKILL 的最高优先级版本锁定规则
直接终止。查询当前提示词时固定使用业务上下文 `promptVersionId`，并传 `version_name=""`。
