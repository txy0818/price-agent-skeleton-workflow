# 规则查询与过滤

本文件仅适用于需要模型自行查询、推导业务规则或映射的场景。修改流程中，用户明确指定的精确
增删改按 [edit-skeleton-workflow.md](edit-skeleton-workflow.md) 直达，不读取本文件，也不调用规则
或关系 MCP 复核用户输入。其他场景仅使用当前可用 MCP 的本轮返回；不得补规则、改映射或复制
全量候选。

## 查询顺序

1. 初始化先调用
   `tool_query_category_ids(ruleGroupId=上下文.ruleGroupId, agentId=上下文.agentId, operator=上下文.operator)`。
   要求 `baseResp.respCode=1` 且 `data.categoryIds` 非空；只使用该去重列表，禁止从历史、名称、
   提示词或模型记忆补类目 ID。响应中的 `ruleGroupId` 与当前上下文不一致时停止。
2. 遍历全部 `data.categoryIds`，逐个调用
   `radar_query_price_rule(categoryId=<当前 categoryId>)`；不得漏查、合并 ID 或只查第一项。每次均
   要求业务成功、`isExist=true` 且 `data.labelCateRule` 完整。记录每个 ID 对应的
   `cateName`、`cateNameTree`、`belongBusiness` 和 `minCateId`，作为本轮唯一类目作用域。
3. 单条 Badcase workflow 不使用本文件，也不查询类目规则或关系映射。
4. 先以全部有效 `ruleTableInfo[].compareItem` 建立集合：集合中精确存在"品牌"时，必须调用
   `radar_query_brand_relation`；过滤后有有效组才输出母子品牌映射表，为 0 组则静默省略。精确存在
   "材质"时，必须调用 `tool_query_material_leaf(operator)`；过滤后有有效行才输出材质引用和对照表，为 0
   行则两者都静默省略。未命中的关系工具不得
   调用，对应映射表不得生成。应调用的工具不可用、失败或响应无法解析时停止，禁止用模型知识兜底。

### 统一作用域过滤

品牌和材质以第二步规则响应中的 `cateName` 为主要过滤依据，`cateNameTree`、`minCateId` 和
`belongBusiness` 用于确认完整作用域。关系响应若提供这些字段，必须与至少一个当前类目一致，任一
已提供字段冲突即删除；`radar_query_brand_relation` 当前响应不提供类目字段时，以当前类目作用域
对品牌主营范围做保守语义筛选，只保留可确认与当前类目直接相关的组。多类目分别过滤后取并集，
不得扩大成“电商全站”。常识只能删除，不得新增、恢复、合并、改名或补别名。

### 类目规则

初始化固定使用 `tool_query_category_ids` 返回的每个 `categoryId` 调 `radar_query_price_rule`。
不要传互相冲突的条件。

类目定位条件来自当前业务上下文或 Agent 详情返回的真实
商品与类目字段。空提示词不是类目来源。

读取 `data.labelCateRule`：

- 作用域：`belongBusiness`、`minCateId`、`cateName`、`cateNameTree`；
- 规则：`searchMethod`、`ruleTableInfo.ruleTableInfo[]` 中的 `compareItem`、`infoSource`、
  `compareLogic`，以及 `specialRuleContent.ruleContent`。

要求 `result=1`、业务响应成功、`isExist=true`、作用域和规则表非空。

以上字段是原始规则响应，查询方法和读取字段不得删除。生成候选提示词时只能使用其去 SKU 投影：
对 `searchMethod`、`infoSource`、`specialRuleContent.ruleContent` 及其他拟写入提示词的响应文本执行
[rule-transformation-guide.md](rule-transformation-guide.md) 的 SKU 清洗。候选全文不得出现任何
大小写形式的 `sku`；被过滤来源只允许删除，不得替换成其他来源或自行补业务规则。`infoSource`
白名单投影全空时，按转换指南输出约定的综合判断优先级；该固定兜底不是对被过滤来源的改写。

### 主子品牌

本轮至少一个有效 `compareItem` 精确等于“品牌”时必须执行本节；过滤后有有效组则必须输出非空母子品牌映射表，
为 0 组则静默省略该表。无“品牌”时跳过查询并禁止输出该表。不得把“过滤后为 0 组”
改写成“规则未涉及品牌映射”，也不得根据特殊规则、基础提示词旧内容或模型常识绕过查询。

初始化在类目规则查询完成后调用 `radar_query_brand_relation`。严格按当前 MCP schema 调用：方法无
入参时直接调用；若 schema 明确提供 `keyword`，全量查询传 `keyword=""`；不得自行添加
`cateName`、`categoryId` 或其他未定义参数。

**先把本轮 `data.groups` 建成唯一候选集合，再由模型按当前类目筛除。模型只能决定保留或删除整组，
不得生成候选集合外的品牌关系，也不得修改组内主品牌或子品牌。**

成功条件：顶层 `result=1`、`error_msg` 为空、`data.baseResp.respCode=1`，且 `data.groups` 可解析。
只读取：

- `groups[].mainBrand.id/brandName/isMainBrand/parentId`；
- `groups[].subBrands[].id/brandName/isMainBrand/parentId`；
- `groups[].subCount`。

每组必须满足：主品牌名称非空、`mainBrand.isMainBrand=true`、`mainBrand.parentId=0`；至少一个
子品牌，且每个子品牌名称非空、`isMainBrand=false`、`parentId=mainBrand.id`；`subCount` 必须等于
有效 `subBrands` 数量。不满足的整组删除，例如 `subBrands=[]`、`subCount=0` 的测试主品牌不输出。
最终文本只使用 `brandName`，不得输出 ID、备注、更新人或更新时间。

该方法返回全量关系且不携带类目字段。必须用本轮 `radar_query_price_rule` 的 `cateName` 为主、
`cateNameTree` 和 `belongBusiness` 为辅进行保守筛选；只保留能确认主营商品与当前类目直接相关的
品牌组，跨行业或不确定组删除。页面或响应中的总组数（例如 192）只是候选总量，不是生成目标。

过滤顺序是硬约束：

1. 先遍历并校验 `data.groups` 的全部组，不得按响应顺序预先截取前 50、前 100 或任意前 N 组；
2. 再按当前 `cateName`、`cateNameTree`、`belongBusiness` 对全部有效组做相关性过滤；
3. 删除跨行业、不确定和测试数据后，才对过滤结果应用 100 组上限；
4. 过滤后不足上限就只输出实际命中组，不得从已删除组回填或用常识补齐。

映射表标题只能使用本轮真实 `cateName` 或 `cateNameTree` 表达适用范围；禁止添加“及相关品牌”、
“全站常见品牌”“相关消费品”等扩大作用域的措辞。标题声明的范围必须与正文每一组一致。

用户明确要求新增、删除、替换某组关系或调整其中成员时不进入本节，也不查询关系库复核，直接以
当前提示词和用户指令完成精确修改。

最终每个 `mainBrand + subBrands[]` 必须能在本轮工具响应中逐项找到；只允许筛除，不允许新增、
合并、补别名或凭常识扩展。**100 组是上限，不是生成目标**；返回或过滤后只有 3 组就只写 3 组。

过滤只决定是否内嵌，不得改变返回的主子关系。由模型自行查询、筛选和生成时最多保留
**100 个主品牌组**，一个 `mainBrand + subBrands[]` 算一组；不足 100 组不得用低相关或不常见
品牌补齐。过滤后仍超过上限时，依次优先：品牌主营商品与当前类目直接相关、在当前类目中更常见；
仍无法区分时保留原响应顺序。上限只能在完整过滤后执行，禁止以“先取前 100”代替过滤。

进入 S3 前必须重新审计最终映射：组数必须为 `1..100`，且每组都能在本轮 MCP 响应中逐项找到，
并能依据当前 `cateName`、`cateNameTree`、`belongBusiness` 与模型常识确认主营范围直接属于当前类目。
存在任一跨行业、不确定组或组数超过 100 时，必须继续筛除，禁止把候选全量、前 100 组或跨类目
关系写入候选提示词。

用户明确输入“新增母子品牌：<关系>”或其他可唯一定位的新增关系时属于精确修改：直接按用户
给出的母品牌和子品牌关系加入，不查询关系库复核，也不受 100 组上限限制。新增后更新标题中的
真实适用范围；不得为了把总数降回 100 而删除原有关系。

生成后必须按上述字段和常识二次审计。例如唯一类目为珠宝、流行首饰或时尚饰品时，只保留可确认
主营珠宝、贵金属或首饰的品牌组；食品、酒水、家电、数码、汽车、普通服饰、家纺、母婴、日化、
美妆、医药、农业等关系全部删除，无法确认主营范围的也删除。不得因为某品牌知名、名称含“金”
或可能销售饰品就推定相关，必须能确认其主营范围直接命中当前类目。

### 同款材质

本轮至少一个有效 `compareItem` 精确等于"材质"时必须执行本节，并在候选全文中保留材质对照表附录；
否则不得读取或执行本节、不得查询材质关系，并禁止输出材质表、材质规则、材质分组结构或"若后续
新增材质"等任何说明。这是双向硬门禁，不得根据特殊规则、基础提示词旧内容、全局材质数据或模型
常识绕过。

用户明确要求新增、删除、替换某个材质组或调整其中成员时，属于 EDIT 精确修改直达分支：不查询
材质关系 MCP 复核，直接以当前提示词和用户指令修改；仍须执行基础版本查询、S3 和提案流程。

初始化调用：

`tool_query_material_leaf(operator=上下文.operator)`

成功条件：`baseResp.respCode=1`。

读取 `materialText[]`：每项已是服务端渲染好的材质组文本行，格式为
`<完整路径>：<叶子材质1>、<叶子材质2>...`，例如 `贵金属·金·足金：999金、纯金、黄金`。
模型无需自行构建树结构；只需对返回的文本行执行以下过滤后直接使用。

**过滤步骤**：
1. **类目过滤**：执行"统一作用域过滤"；以本轮 `cateName`（辅以 `cateNameTree`、`belongBusiness`）
   为依据，只保留与当前类目直接相关的材料行，明显无关或不确定的行删除。
   例如唯一类目为美妆工具时，只保留可能构成刷具、粉扑、容器或工具主体的材质行；
   服饰专用面料、皮草羽绒、建筑工业专用材料等明显无关行必须删除。不确定项删除。
2. **数量上限**：过滤后最多保留 50 行；不足 50 行时保持实际数量，不得补齐。

工具响应成功且 `materialText[]` 为空，或完成类目过滤后为 0 行，均是允许的真实结果，不得停止、
不得补齐。此时静默省略材质引用行和材质表，不得输出空结果说明。

进入 S3 前记录 `materialGroupCount = min(过滤后行数, 50)`。

输出时将过滤后的文本行**原样**写入材质对照表附录，不得改写路径或成员名称，禁止模型按常识
新建分组或补同义词。**50 行是上限，不是生成目标**；实际不足时只输出实际行数。

生成后二次审计：每行格式是否为 `**路径**：成员1、成员2`；行数是否不超过 50；内容是否来自
本轮 `materialText[]` 过滤结果，无任何模型自行添加的内容。

## 流程范围

| 流程 | 类目规则 | 品牌 | 材质 |
|---|---|---|---|
| 初始化 | `tool_query_category_ids` 后逐 ID 查询 | 调用 `radar_query_brand_relation`，主要按 `cateName` 过滤 | 调用 `tool_query_material_leaf(operator)`，对返回文本行按 `cateName` 过滤，最多 50 行 |
| 修改 | 仅非精确修改时按需查询 | 仅非精确修改且工具存在时查询 | 仅非精确修改且工具存在时查询 |

跨类目时分别建立作用域，不得混用。相同工具、入参和作用域可复用本轮结果。

## 骨架体量

初始化目标约 1 万字：完整保留有效 `compareItem`、来源优先级、匹配逻辑和明确例外；品牌、
材质只保留当前作用域必要映射；模型自行生成时母子品牌最多 100 组、材质最多 50 组，用户明确
新增的母子品牌不受 100 组限制。过长时精简行文或改成运行时查询指令，不得硬截断规则。

## 停止条件

顶层或业务响应失败、类目规则/作用域为空、关系响应无法解析、无法可靠过滤、或指定类目与返回
作用域冲突时停止。不得因本轮未加载某映射而删除基础提示词的其他章节。
