## 使用边界

- 本文件是初始化和修改提示词时必须遵循的完整结构规范，规定章节、字段、表达粒度和输出格式。
- 本文件中的“使用边界”“生成原则”“固定章节与内容要求”“比价项写法细则”“映射表写法细则”
  “JSON 输出字段规则”和“完成检查”均为生成器内部规范，只用于约束候选提示词的生成与校验，
  **不是候选提示词正文，禁止将这些规范句子复制、改写或解释后写入 `prompt_content`**。
- 只有“完整格式模板”中从 `# 角色` 开始至该模板的 `# 输出格式` 结束的内容，才是候选提示词正文
  结构；生成时替换尖括号占位符并填入本轮真实业务数据。不得把“完整格式模板”标题、模板前后的
  规范说明、检查过程或生成依据写入 `prompt_content`。
- 本文件不提供当前业务事实。模板中的尖括号内容必须替换为本轮可信数据，不得原样保留。
- 比价项、适用类目、优先级、综合判定、阈值、否决关系和例外必须来自本轮
  `radar_query_price_rule.data.labelCateRule`。
- 上述响应中的文本写入候选提示词前必须按
  [rule-transformation-guide.md](rule-transformation-guide.md) 删除全部 SKU 相关内容（大小写不敏感）。
  必须先按 `>`、`/`、`=` 拆成最小来源片段，再删除含 `sku` 的片段；不得因一个大段含 SKU 而连带
  删除其中以 `/` 或 `=` 分隔的合法来源。禁止把 SKU 来源替换成允许来源。剩余片段中，包含
  “商品属性”“商品标题”“主图”的项分别归一为`商品属性`、
  `商品标题`、`主图`，例如`主图文字说明`归一为`主图`。候选全文不得出现任何形式的 `sku`。
- 母子品牌和材质映射必须来自本轮对应关系工具，主要按逐个 CategoryId 查询规则得到的
  `cateName` 过滤，再用 `cateNameTree`、`minCateId`、`belongBusiness` 校验冲突。
- 禁止读取或使用 `full-skeleton-example.md`、`rule-writing-examples.md` 及历史完整提示词作为生成范式；
  它们可能含旧业务事实。结构只以本文件为准，业务内容只以本轮可信响应为准。
- 用户明确给出的精确增删改属于授权修改目标，可按修改 workflow 最小写入；不得借格式整理扩展为
  用户没有提出、MCP 也没有返回的新业务规则。

## 生成原则

### 1. 结构完整

完整提示词必须包含以下章节，并严格保持顺序：

1. `# 角色`
2. `# 输入说明`
3. `# 执行步骤`
4. `# 判定规则`
5. `## 总原则`
6. `## 比价项`
7. `## 映射表`（品牌或材质过滤后至少一项非空时才输出）
8. `# 图片说明`
9. `# 输出格式`

一级章节之间使用独立的 `---` 分隔。除条件性 `## 映射表` 外，不得改名、合并、调序或省略固定章节。

凡是正文中的连续业务编号序列，在新增、删除或调序后必须整体重新编号，保持从 1 开始连续递增，
不得出现缺号、重复号或沿用删除前序号。该规则至少适用于 `### 1. <比价项>` 形式的比价项章节
和母子品牌映射条目；不改变固定的 `Step0`～`Step3` 名称。母子品牌标题不写组数。

### 2. 规则完整

- 保留规则查询返回的全部生效比价项、否决关系、例外条件和来源优先级。
- 不适用项从适用范围、执行步骤、判定规则和最终 `extracted` 中整体省略。
- 不得把相近名称的比价项合并，不得把查不到的名称替换成近义项。
- 不得为了缩短正文删除关键规则；允许合并同义重复表述，但不能改变业务含义。
- 不得从编码、数字前缀、模糊外观或常识推断 MCP 未提供的年份、代际、版本、材质或品牌关系。

### 3. 映射受控

- `ruleTableInfo[].compareItem` 精确包含“品牌”时必须查询并过滤母子品牌关系；过滤后非空才输出品牌
  映射表，为空则静默省略。精确包含“材质”时必须查询并过滤材质关系；过滤后非空才输出材质引用和
  材质对照表，为空则两者都静默省略。缺少对应比价项
  时必须省略对应表，即使关系 MCP 有数据或基础正文原来有表。
  应调用的工具失败或无法解析时必须停止，不得伪造映射。
- 材质最多 50 个材质组，一个主材质或同义材质集合算一组。
- 映射数量、过滤、母子品牌连续编号和精确修改例外统一执行
  [rule-transformation-guide.md](rule-transformation-guide.md)；本文件不重复定义。每个映射及成员必须逐项存在于本轮对应关系工具响应中，
  只允许筛除和格式化，禁止补齐、合并、改名、推断或使用模型记忆生成。
- 材质分组名称、成员和同组关系必须逐项来自同次 `radar_query_material_relation` 响应：组名取从
  一级根节点到真实父节点的完整路径并用`·`连接，成员只取该父节点下 `isLeaf=true` 的直接末端叶子；
  路径不得漏级、增级、调序或改名。少于两个直接叶子的节点不输出为对照组。母子品牌必须逐组来自
  同次 `radar_query_brand_relation` 响应。生成前先建立工具返回的允许集合，生成后逐项校验；任何
  集合外内容直接删除，禁止用常识补充。
- 用户明确指定单个母子品牌或材质关系的新增、删除、替换或成员调整时，该指令本身是可信修改
  目标；具体边界按转换指南执行。
- 删除跨行业、无法确认相关性和当前范围不需要的映射；标题只写真实适用范围，不写组数，禁止
  “适用于当前电商全站常见品牌”等扩大范围描述。
- 映射数据过长时只保留通过作用域与常识过滤后的高相关分组；不得复制全量候选，也不得用
  “其余组”“运行时查询”等说明代替未展示条目。

### 4. 长度受控

全文粗略控制在 1 万字以内，包括规则和映射表。接近上限时：

1. 先删除解释性重复句和重复示例；
2. 再合并同义表达；
3. 最后按 `rule-loading-policy.md` 仅保留当前类目直接相关的高优先级映射。

不得通过删除生效比价项、否决关系、例外或 JSON 字段来缩短正文，也不得用“其余组”“运行时
查询”等占位说明代替实际保留的映射。

## 固定章节与内容要求

### `# 角色`

明确模型身份、任务目标、左右商品关系、必须逐项执行以及只输出结构化 JSON。保持简洁，不在角色
章节提前展开业务规则。

### `# 输入说明`

必须说明：

- 输入含 `category`，是用 `>` 分隔的多级类目路径；
- `category` 决定哪些比价项生效；
- 使用表格逐行列出比价项及本轮真实 `cateNameTree`；
- 不适用项不抽取、不匹配、不输出、不参与综合判定。

适用范围必须使用本轮规则返回的真实 `cateNameTree`，将 `/` 转成 `>`；不得写“全类目”、简称或
从完整示例复制类目。每个真实比价项必须独占一行并保持 `ruleTableInfo[]` 顺序；适用范围相同也
不得把多个比价项合并到同一单元格。这些是生成和校验约束，不是提示词正文：候选提示词只输出
`category` 说明、真实表格和“不适用的比价项不参与判定”，禁止把本段元规则复制到表格下方。

### `# 执行步骤`

必须完整包含 `Step0` 至 `Step3`，且顺序固定：

- `Step0`：读取 `category`，确定本次生效比价项子集；
- `Step1`：从允许来源逐项抽取左右 `value` 和 `source`；
- `Step2`：按各比价项规则生成 `match` 和 `reason`；
- `Step3`：只能基于生效比价项的 `match` 得出 `result`。

`Step3` 必须使用下方固定通用 Step3，并明确禁止跳过 Step1、Step2 直接给结果。当真实规则存在
`compareLogic=货号匹配逻辑` 时，使用 [enums.md](enums.md) 规定的完整货号 Step3 替换通用 Step3，
不得把两套聚合规则并列。除货号逻辑外，不得根据其他 `compareLogic` 自行改写 Step3；本轮真实特殊
规则若明确规定综合判定例外，才在不冲突的前提下追加该真实例外。

“品牌”的母子品牌映射和品牌互认结果只用于 Step2 计算品牌比价项的 `match`，不得仅因比价项名称为
“品牌”就在 Step3 新增固定否决或放宽逻辑。只有本轮真实 `specialRuleContent.ruleContent` 或综合判定
规则明确规定品牌相关的否决、放宽或例外时，才将该真实规则转换到 Step3。

### `# 判定规则`

#### `## 总原则`

至少覆盖：

- 生效比价项之间的综合关系；
- 高优先级信息不被低优先级覆盖；
- 多来源相同时 `source` 使用 `+` 拼接；
- `result` 和总 `reason` 只能基于生效比价项；
- 禁止引入比价项以外的信息；
- 禁止从编码或模糊线索推断不存在的属性；
- 本轮规则返回的特殊例外。

#### `## 比价项`

本节只规定章节位置与标题层级。每个生效比价项独立使用三级标题并连续编号；具体字段、来源过滤、
匹配拼接以及品牌、材质、货号的特殊结构全部以
[rule-transformation-guide.md](rule-transformation-guide.md) 为唯一规范，不在此重复定义。

删除任一比价项后，后续所有 `### N. 比价项名称` 必须按当前顺序连续前移。例如删除
`### 6. 型号` 后，原 `### 7. 货号` 必须改为 `### 6. 货号`，依次类推。

### `## 映射表`

有效 `compareItem` 包含“品牌”时必须查询并过滤品牌关系；非空时按固定格式输出，为空时省略品牌表。
有效 `compareItem` 包含“材质”时必须查询并过滤材质关系；非空时材质章节写引用并输出材质表，为空时
引用和材质表都省略。两者都为空时省略整个 `## 映射表` 章节及相邻多余分隔线。不得输出空结果说明、
门控说明、编造条目或完整示例内容。

### `# 图片说明`

必须说明第 1 张和第 2 张图片分别对应哪一侧商品，并列出本轮允许通过主图判断的生效比价项。
图片只是允许来源之一；高优先级属性或标题已有明确信息时，不得被低优先级图片判断覆盖。

### `# 输出格式`

必须要求只输出合法 JSON，不输出解释、注释或 Markdown 围栏；提供完整、可解析的 JSON 示例，并
逐条写明字段规则。

# 输出格式

严格只输出JSON，禁止额外文字、注释或```符号。

**`extracted`中只包含生效的比价项**：不适用的比价项按`category`裁剪后不出现在`extracted`对象中，不抽取、不输出空对象、不参与综合判定。

```json
{
  "result": "same或different",
  "reason": "一句话关键判定依据",
  "confidence": 0.0,
  "extracted": {
    "<生效比价项1>": {
      "left": {
        "value": "",
        "source": ""
      },
      "right": {
        "value": "",
        "source": ""
      },
      "match": true,
      "reason": ""
    },
    "<生效比价项2>": {
      "left": {
        "value": "",
        "source": ""
      },
      "right": {
        "value": "",
        "source": ""
      },
      "match": true,
      "reason": ""
    },
    "key_diff_point": ""
  }
}
```

字段规则：

- `extracted`仅包含按`category`生效的比价项；不适用项整体省略，不输出空对象。
- `confidence`取值范围为`0.0`～`1.0`（含边界）的浮点数，越大表示判定把握越高；示例中的`0.0`仅为占位值。必须输出具体数字字面量（如`0.85`），严禁输出`0.0~1.0`、`0.0-1.0`等区间记法。
- `value`抽取不到时填`"缺失"`，`source`填`""`。
- `source`仅允许三种标准来源：`商品属性`、`商品标题`、`主图`；其他来源填`""`。
- `match=true`表示匹配或不影响判断，`match=false`表示不匹配；`match=false`必须能由对应比价项规则解释。
- 多来源信息相同时，`source`使用`+`拼接，如`"商品属性+商品标题"`。
- 材质`value`如果分多部位，必须按部位输出，格式为`帮面:XX;鞋底:YY;鞋垫:ZZ`，缺失的部位省略；服装等其他类目使用本轮规则规定的真实部位名。
- `key_diff_point`始终保留；`result="same"`时必须为空字符串，`result="different"`时填写导致否决的关键差异点。
````

上面的`字段规则：`标题及其下方8条规则是候选提示词的固定必选正文，不是格式说明或可选注释。
生成时必须逐条保留，不得概括、合并、改写或省略；JSON代码围栏结束不代表`# 输出格式`章节结束，
只有8条字段规则全部输出后该章节才完整。具体类目不涉及材质时，也必须保留多部位材质的字段格式规则，
因为它属于输出协议约束。

生成候选正文时，先把`# 输出格式`至第8条`key_diff_point`规则作为一个不可拆分的固定块完整复制，
再生成和填充前面的动态业务章节。不得先生成JSON后再“视剩余长度”决定是否追加字段规则；任何长度
控制都只能压缩动态业务内容，不能裁剪这个固定块。

## 比价项写法细则

比价项正文的唯一转换与校验规范是
[rule-transformation-guide.md](rule-transformation-guide.md)。本节仅保留运行时抽取和输出约束，
不重复定义来源过滤、匹配兜底或特殊项结构。

### 抽取规则

- `value` 必须忠实保留影响判定的名称、数值、单位、含量和部位信息。
- 单一属性可直接输出值；多值或多部位信息按当前比价项规则规定的稳定格式输出。
- 材质存在多成分时完整保留成分与含量；存在多部位时按 `部位:值;部位:值` 输出。
- 图片只用于规则允许从主图判断的比价项，不得从模糊图片推断编码、精确含量或不可见属性。

### 运行时匹配

- 先完成左右抽取，再进行归一化和匹配，不得从最终标签倒推抽取值。
- `match` 必须对应当前比价项的规则；`reason` 说明左右值如何命中该规则。
- 默认、缺失、不影响判断、单独不构成否决等语义必须以本轮规则为准，不得从完整示例继承。
- 涉及阈值、集合交集、映射同组、多部位逐项比较或特殊例外时，完整写出条件和边界。

## 映射表写法细则

### 母子品牌

- 查询门禁、类目与常识过滤、100 组上限、精确修改例外以及删除后连续编号，全部以
  [rule-transformation-guide.md](rule-transformation-guide.md) 的“品牌”小节为唯一规范。
- 标题格式：`### 母子品牌映射表（<真实适用类目或业务范围>）`，禁止写动态组数。
- 相同主品牌不得拆成多组；同一子品牌关系冲突时停止，不得自行选择。
- 仅当材质对照表也需输出时，最后一条母子品牌之后空一行并单独输出 `---`，再空一行输出材质
  对照表标题；禁止加粗分隔线或把 `---` 与任一标题写在同一行。

### 材质分组

- 有效 `compareItem` 精确包含“材质”时才允许加载并输出材质对照表附录；否则整个小节必须省略，
  且禁止输出“当前未涉及材质”“若后续新增材质”“系统存在全局材质分组”等说明或未来使用规范。
- 标题固定为：`### 材质对照表（同组内可互匹配，跨组不可）`。
- 候选正文中对应的材质比价项章节必须同时存在固定引用
  `- **材质对照表**：见下方附录。`；只有引用没有本附录，或只有本附录没有引用，均不合格。
- 过滤后有有效组时按真实组输出；为 0 组时省略材质章节中的附录引用和整个材质表，不得输出空结果
  说明、补组或复制示例。
- 品牌和材质过滤结果都为空时，省略整个 `## 映射表` 章节。“以下两个子表分别受门控”等生成器内部
  说明任何情况下都不得写入候选正文。
- 最终全文出现母子品牌子表标题时，正文必须至少存在 1 条真实 `母品牌→子品牌` 记录；出现材质子表
  标题时，正文必须至少存在 1 个通过本轮节点账本校验的真实材质组。标题存在而对应计数为 0，或正文
  含“无符合”“无可输出”“未命中”“暂无”等空结果文案，均为硬失败，必须删除整个空子表后重新审计。
- 每组使用 `**组名**：成员1、成员2`。分组键、组名和成员严格按
  [rule-loading-policy.md](rule-loading-policy.md) 的 `(parentId,isLeaf)` 算法生成，不得由模型自行聚类。
- 不得把工艺名、营销词或跨行业材料自行归入某组；无法确认时不输出。
- “同组可匹配”是否存在阈值、部位或含量例外，必须以本轮规则为准并写入对应比价项章节。
- 最多 50 个材质组；实际不足时不补齐。

## JSON 输出字段规则

### 顶层字段

- `result`：仅允许当前协议规定的 `same` 或 `different`。
- `reason`：一句话说明综合判定的关键依据，只引用生效比价项。
- `confidence`：`0.0`～`1.0` 的具体数字字面量，不加引号，不写范围。
- `extracted`：对象，只包含生效比价项和始终存在的 `key_diff_point`。

### 每个生效比价项

- `left.value`、`right.value`：左右商品抽取值；抽取不到填 `"缺失"`。
- `left.source`、`right.source`：只允许空字符串，或由`商品属性`、`商品标题`、`主图`使用 `+` 连接。
- `match`：布尔值，不得写成字符串。
- `reason`：说明该项匹配或不匹配所依据的真实值和规则。

### `key_diff_point`

- 字段始终位于 `extracted` 内并始终保留。
- `same` 时为 `""`。
- `different` 时只写导致最终否决的生效比价项差异，不引入未参与判定的信息。

## 完成检查

生成候选全文后逐项检查，任一项不满足都必须先修复再调用校验工具：

### 结构

- 是否包含全部固定章节并保持正确顺序？
- 一级章节之间是否使用 `---`？
- 是否完整包含 `Step0` 至 `Step3`，且没有跳过抽取或匹配直接给结果？
- 是否删除全部尖括号占位符、`TODO`、空标题和无内容条目？

### 业务规则

- 是否只使用本轮 MCP 返回的比价项、类目、优先级、阈值、例外和映射？
- 是否保留全部生效比价项、否决关系和综合判定例外？
- 是否按 `category` 裁剪，并从规则章节和 JSON 中整体删除不适用项？
- 是否没有从编码、常识、完整示例或相近名称发明业务事实？
- 是否已将来源归一为仅含`商品属性`、`商品标题`、`主图`，删除全部 SKU、比价维度、详情及其他
  非法来源，且未把被删除来源改写成允许来源；投影全空时是否使用固定综合判断兜底？
- 是否先抽取、再匹配、最后综合判断？
- 每个比价项是否先写专属规则、再写对应兜底逻辑，且两者均未遗漏？
- 每个比价项是否只按顺序写入本轮特殊规则和真实 `compareLogic` 兜底，没有按名称补写品牌、货号、
  材质或其他固定规则？

### 映射与长度

- 模型自行生成的母子品牌是否不超过 100 组、材质是否不超过 50 组，并已删除低相关、不常见、跨行业与不确定项？用户明确新增的母子品牌是否已直接加入且未受数量限制？
- 母子品牌标题是否为三级标题、只写真实范围且不写组数？是否已丢弃旧序号并整体重写为连续
  `1..N`，格式是否统一为 `母品牌→子品牌1|子品牌2`？
- 材质组名和成员是否来自可信映射，且没有自行归类？
- 全文是否大体在 1 万字以内，且没有为压缩长度删除规则？

### JSON

- JSON 示例是否可解析，且包含 `result`、`reason`、`confidence`、`extracted`？
- `extracted` 是否只包含生效比价项，没有不适用项或空对象？
- 每个比价项是否包含左右 `value/source`、布尔 `match` 和 `reason`？
- `confidence` 是否为范围内的具体数字字面量，而不是字符串或区间？
- `source` 是否只使用三种允许值并按 `+` 拼接？
- 多部位材质是否按 `部位:值;部位:值` 输出？
- `key_diff_point` 是否始终存在，并与 `result` 一致？
- JSON 围栏后是否仍完整包含`字段规则：`及其下方8条固定规则？缺少任一条都不得调用校验工具。
- 每个比价项是否默认只保留必要字段，所有额外条目都有本轮可信规则的直接依据且不与其他条目重复？

字段规则的8个必含语义逐项检查，不能只检查标题：

1. `extracted`仅包含按`category`生效的比价项；
2. `confidence`必须为`0.0`～`1.0`范围内的具体数字字面量；
3. 抽取不到时`value="缺失"`且`source=""`；
4. `source`只允许`商品属性`、`商品标题`、`主图`及其`+`组合；
5. `match`必须为布尔值并说明`true`、`false`含义；
6. 相同信息来自多个来源时使用`+`拼接；
7. 多部位材质使用`部位:值;部位:值`；
8. `key_diff_point`始终保留，并与`result`一致。
