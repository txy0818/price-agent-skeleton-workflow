## 使用边界

- 本文件是初始化和修改提示词时必须遵循的完整结构规范，规定章节、字段、表达粒度和输出格式。
- 本文件不提供当前业务事实。模板中的尖括号内容必须替换为本轮可信数据，不得原样保留。
- 比价项、适用类目、优先级、综合判定、阈值、否决关系和例外必须来自本轮
  `radar_query_price_rule.data.labelCateRule`。
- 母子品牌和材质映射必须来自本轮对应关系工具，并按当前 `cateName`、`belongBusiness` 过滤。
- [full-skeleton-example.md](full-skeleton-example.md) 只用于展示结构和表达方式，其中的类目、规则、
  品牌、材质、阈值和映射均不是当前业务事实，不得复制到候选提示词。
- 用户明确给出的精确增删改属于授权修改目标，可按修改 workflow 最小写入；不得借格式整理扩展为
  用户没有提出、MCP 也没有返回的新业务规则。

## 生成原则

### 1. 结构完整

完整提示词必须包含以下章节，并严格保持顺序：

1. `# 角色`
2. `# 输入说明`
3. `# 执行步骤`
4. `# 判定规则`
5. `## 总原则`
6. `## 比价项`
7. `## 映射表`
8. `# 图片说明`
9. `# 输出格式`

一级章节之间使用独立的 `---` 分隔。不得改名、合并、调序或省略固定章节。

凡是正文中的连续业务编号序列，在新增、删除或调序后必须整体重新编号，保持从 1 开始连续递增，
不得出现缺号、重复号或沿用删除前序号。该规则至少适用于 `### 1. <比价项>` 形式的比价项章节
和母子品牌映射条目；不改变固定的 `Step0`～`Step3` 名称。带数量的标题必须同步按最终正文重新计数。

### 2. 规则完整

- 保留规则查询返回的全部生效比价项、否决关系、例外条件和来源优先级。
- 不适用项从适用范围、执行步骤、判定规则和最终 `extracted` 中整体省略。
- 不得把相近名称的比价项合并，不得把查不到的名称替换成近义项。
- 不得为了缩短正文删除关键规则；允许合并同义重复表述，但不能改变业务含义。
- 不得从编码、数字前缀、模糊外观或常识推断 MCP 未提供的年份、代际、版本、材质或品牌关系。

### 3. 映射受控

- 模型自行查询、筛选和生成时，母子品牌最多 100 个主品牌组，一个 `mainBrand + subBrands[]` 算一组。
- 材质最多 50 个材质组，一个主材质或同义材质集合算一组。
- 母子品牌不足 100 组、材质不足 50 组时不补齐；超过上限时按 `rule-loading-policy.md` 优先保留当前类目和业务范围相关且较常见的组，低相关、不常见或不确定的品牌不内嵌。
- 用户明确输入“新增母子品牌：<关系>”或等价的精确新增指令时，直接加入用户给出的关系，不受 100 组上限限制；新增后更新标题中的实际组数，不得为满足上限删除原有关系。
- 删除跨行业、无法确认相关性和当前范围不需要的映射。生成后重新计数，标题中的实际组数必须与正文一致。
- 映射数据过长时宁可保留运行时查询说明和当前必要分组，也不得直接复制全量候选。

### 4. 长度受控

全文粗略控制在 1 万字以内，包括规则和映射表。接近上限时：

1. 先删除解释性重复句和重复示例；
2. 再合并同义表达；
3. 最后把非必要的长映射改为运行时查询说明。

不得通过删除生效比价项、否决关系、例外或 JSON 字段来缩短正文。

## 固定章节与内容要求

### `# 角色`

明确模型身份、任务目标、左右商品关系、必须逐项执行以及只输出结构化 JSON。保持简洁，不在角色
章节提前展开业务规则。

### `# 输入说明`

必须说明：

- 输入含 `category`，是用 `>` 分隔的多级类目路径；
- `category` 决定哪些比价项生效；
- 使用表格列出比价项及其适用类目；
- 全类目生效项与部分类目生效项要明确区分；
- 不适用项不抽取、不匹配、不输出、不参与综合判定。

适用范围必须使用本轮规则返回的真实类目前缀，不得从完整示例复制类目。

### `# 执行步骤`

必须完整包含 `Step0` 至 `Step3`，且顺序固定：

- `Step0`：读取 `category`，确定本次生效比价项子集；
- `Step1`：从允许来源逐项抽取左右 `value` 和 `source`；
- `Step2`：按各比价项规则生成 `match` 和 `reason`；
- `Step3`：只能基于生效比价项的 `match` 得出 `result`。

`Step3` 必须写入本轮规则中的综合判定条目及例外，并明确禁止跳过 Step1、Step2 直接给结果。

### `# 判定规则`

#### `## 总原则`

至少覆盖：

- 生效比价项之间的综合关系；
- 高优先级信息不被低优先级覆盖；
- 多来源相同时 `source` 使用 `+` 拼接；
- `result` 和总 `reason` 只能基于生效比价项；
- 禁止引入比价项以外的信息；
- 禁止从编码或模糊线索推断不存在的属性；
- 本轮规则返回的特殊例外。

#### `## 比价项`

每个生效比价项独立使用三级标题并连续编号。每项至少写明真实的来源优先级和核心匹配规则；
部分类目生效时补充适用类目。规则返回了抽取、归一化、否决、例外或特殊边界时，继续用具名条目展开，
不得全部压缩成一句泛化描述。

删除任一比价项后，后续所有 `### N. 比价项名称` 必须按当前顺序连续前移。例如删除
`### 6. 型号` 后，原 `### 7. 货号` 必须改为 `### 6. 货号`，依次类推。

### `## 映射表`

存在品牌或材质映射时，必须按本文件的固定格式输出。某类映射经可信查询后确实不存在时，说明
本轮未取得可内嵌映射，不得编造条目或从完整示例复制。

### `# 图片说明`

必须说明第 1 张和第 2 张图片分别对应哪一侧商品，并列出本轮允许通过主图判断的生效比价项。
图片只是允许来源之一；高优先级属性或标题已有明确信息时，不得被低优先级图片判断覆盖。

### `# 输出格式`

必须要求只输出合法 JSON，不输出解释、注释或 Markdown 围栏；提供完整、可解析的 JSON 示例，并
逐条写明字段规则。

按本轮查询结果为每个生效比价项生成一个章节，并保持连续编号。不得输出不存在的比价项，也不得

# 输出格式

严格只输出JSON，禁止额外文字、注释或```符号。

**`extracted`中只包含生效的比价项**：不适用的比价项按`category`裁剪后不出现在`extracted`对象中，不抽取、不输出空对象、不参与综合判定。

```json
{
  "result": "same或different",
  "reason": "一句话关键判定依据",
  "confidence": 0.0,
  "extracted": {
    "<生效比价项1>": {
      "left": {
        "value": "",
        "source": ""
      },
      "right": {
        "value": "",
        "source": ""
      },
      "match": true,
      "reason": ""
    },
    "<生效比价项2>": {
      "left": {
        "value": "",
        "source": ""
      },
      "right": {
        "value": "",
        "source": ""
      },
      "match": true,
      "reason": ""
    },
    "key_diff_point": ""
  }
}
```

字段规则：

- `extracted`仅包含按`category`生效的比价项；不适用项整体省略，不输出空对象。
- `confidence`取值范围为`0.0`～`1.0`（含边界）的浮点数，越大表示判定把握越高；示例中的`0.0`仅为占位值。必须输出具体数字字面量（如`0.85`），严禁输出`0.0~1.0`、`0.0-1.0`等区间记法。
- `value`抽取不到时填`"缺失"`，`source`填`""`。
- `source`仅限三种：`商品属性`（商品属性栏）、`商品标题`（商品标题）、`主图`（商品主图）；不属于这三种的来源填`""`。
- `match=true`表示匹配或不影响判断，`match=false`表示不匹配；`match=false`必须能由对应比价项规则解释。
- 多来源信息相同时，`source`使用`+`拼接，如`"商品属性+商品标题"`。
- 材质`value`如果分多部位，必须按部位输出，格式为`帮面:XX;鞋底:YY;鞋垫:ZZ`，缺失的部位省略；服装等其他类目使用本轮规则规定的真实部位名。
- `key_diff_point`始终保留；`result="same"`时必须为空字符串，`result="different"`时填写导致否决的关键差异点。
````

上面的`字段规则：`标题及其下方8条规则是候选提示词的固定必选正文，不是格式说明或可选注释。
生成时必须逐条保留，不得概括、合并、改写或省略；JSON代码围栏结束不代表`# 输出格式`章节结束，
只有8条字段规则全部输出后该章节才完整。具体类目不涉及材质时，也必须保留多部位材质的字段格式规则，
因为它属于输出协议约束。

生成候选正文时，先把`# 输出格式`至第8条`key_diff_point`规则作为一个不可拆分的固定块完整复制，
再生成和填充前面的动态业务章节。不得先生成JSON后再“视剩余长度”决定是否追加字段规则；任何长度
控制都只能压缩动态业务内容，不能裁剪这个固定块。

## 比价项写法细则

### 来源优先级

- 使用 `>` 表示来源优先顺序，使用 `/` 表示同等参考；必须与本轮规则返回含义一致。
- 高优先级来源有明确值时使用该值；只有高优先级缺失或不明确时才看低优先级。
- 多个允许来源给出相同信息时保留合并来源；信息冲突时按优先级选择，不得自行投票。

### 抽取规则

- `value` 必须忠实保留影响判定的名称、数值、单位、含量和部位信息。
- 单一属性可直接输出值；多值或多部位信息按当前比价项规则规定的稳定格式输出。
- 材质存在多成分时完整保留成分与含量；存在多部位时按 `部位:值;部位:值` 输出。
- 图片只用于规则允许从主图判断的比价项，不得从模糊图片推断编码、精确含量或不可见属性。

### 匹配规则

- 先完成左右抽取，再进行归一化和匹配，不得从最终标签倒推抽取值。
- `match` 必须对应当前比价项的规则；`reason` 说明左右值如何命中该规则。
- 默认、缺失、不影响判断、单独不构成否决等语义必须以本轮规则为准，不得从完整示例继承。
- 涉及阈值、集合交集、映射同组、多部位逐项比较或特殊例外时，完整写出条件和边界。

### 规则展开粒度

默认每个普通比价项只写`优先级`和`匹配`，仅部分类目适用时再写`适用类目`。禁止把
`抽取规则`、`归一化规则`、`例外与边界`、`具体规则名`作为每项固定栏目。若本轮可信规则明确包含
下列独立条件，而且并入`优先级`或`匹配`会丢失条件或边界，才允许展开。只有
`radar_query_price_rule.data.labelCateRule`明确返回规则名称时才能原样使用该名称；没有名称时并入
`匹配`，不得自拟标题：

- 抽取来源和优先级；
- 归一化、符号处理或同义词；
- 映射互认或同组匹配；
- 数值或含量阈值；
- 多部位、多成分或多品牌处理；
- 无效值和缺失值处理；
- 单独否决、不得单独否决及综合判定例外。

以下情况一律视为过度展开，生成后必须删除：

- 每个比价项都具有完全相同的一组`抽取规则`、`归一化规则`、`例外与边界`和`具体规则名`；
- 条目内容只是把`优先级`或`匹配`换一种说法重复一遍；
- 条目包含本轮规则未返回的行业常识、示例品牌、推测性归一化方式或宽泛边界；
- `具体规则名`只是“通用匹配逻辑”等模型自拟名称，而非可信规则返回的真实名称。

## 映射表写法细则

### 母子品牌

- 标题格式：`### 母子品牌映射表（<范围><实际组数>组）`。
- 每个主品牌组独占一行，使用从 1 开始连续递增的阿拉伯数字序号。
- 母品牌与子品牌之间只使用 `→`，多个子品牌之间只使用半角 `|`。
- 禁止使用无序列表、Markdown 加粗、中文冒号、顿号或逗号分隔子品牌。
- 相同主品牌不得拆成多组；同一子品牌关系冲突时停止，不得自行选择。
- 模型自行生成时最多 100 个主品牌组；用户明确新增的关系不受此限制。标题中的组数必须与实际编号末项一致。
- 删除任一母子品牌组后，后续条目必须连续前移并重新编号；例如删除第 6 组后，原第 7 组改为
  第 6 组，直至末项。重新编号后再更新标题中的实际组数。

### 材质分组

- 标题固定为：`### 材质对照表（同组内可互匹配，跨组不可）`。
- 每组使用 `**组名**：成员1、成员2`，组名和成员必须来自本轮过滤后的可信映射。
- 不得把工艺名、营销词或跨行业材料自行归入某组；无法确认时不输出。
- “同组可匹配”是否存在阈值、部位或含量例外，必须以本轮规则为准并写入对应比价项章节。
- 最多 50 个材质组；实际不足时不补齐。

## JSON 输出字段规则

### 顶层字段

- `result`：仅允许当前协议规定的 `same` 或 `different`。
- `reason`：一句话说明综合判定的关键依据，只引用生效比价项。
- `confidence`：`0.0`～`1.0` 的具体数字字面量，不加引号，不写范围。
- `extracted`：对象，只包含生效比价项和始终存在的 `key_diff_point`。

### 每个生效比价项

- `left.value`、`right.value`：左右商品抽取值；抽取不到填 `"缺失"`。
- `left.source`、`right.source`：只允许空字符串或由 `商品属性`、`商品标题`、`主图` 使用 `+` 连接。
- `match`：布尔值，不得写成字符串。
- `reason`：说明该项匹配或不匹配所依据的真实值和规则。

### `key_diff_point`

- 字段始终位于 `extracted` 内并始终保留。
- `same` 时为 `""`。
- `different` 时只写导致最终否决的生效比价项差异，不引入未参与判定的信息。

## 完成检查

生成候选全文后逐项检查，任一项不满足都必须先修复再调用校验工具：

### 结构

- 是否包含全部固定章节并保持正确顺序？
- 一级章节之间是否使用 `---`？
- 是否完整包含 `Step0` 至 `Step3`，且没有跳过抽取或匹配直接给结果？
- 是否删除全部尖括号占位符、`TODO`、空标题和无内容条目？

### 业务规则

- 是否只使用本轮 MCP 返回的比价项、类目、优先级、阈值、例外和映射？
- 是否保留全部生效比价项、否决关系和综合判定例外？
- 是否按 `category` 裁剪，并从规则章节和 JSON 中整体删除不适用项？
- 是否没有从编码、常识、完整示例或相近名称发明业务事实？
- 是否先抽取、再匹配、最后综合判断？

### 映射与长度

- 模型自行生成的母子品牌是否不超过 100 组、材质是否不超过 50 组，并已删除低相关、不常见、跨行业与不确定项？用户明确新增的母子品牌是否已直接加入且未受数量限制？
- 母子品牌标题组数是否与实际条目一致，编号是否连续，格式是否统一为 `母品牌→子品牌1|子品牌2`？
- 材质组名和成员是否来自可信映射，且没有自行归类？
- 全文是否大体在 1 万字以内，且没有为压缩长度删除规则？

### JSON

- JSON 示例是否可解析，且包含 `result`、`reason`、`confidence`、`extracted`？
- `extracted` 是否只包含生效比价项，没有不适用项或空对象？
- 每个比价项是否包含左右 `value/source`、布尔 `match` 和 `reason`？
- `confidence` 是否为范围内的具体数字字面量，而不是字符串或区间？
- `source` 是否只使用三种允许值并按 `+` 拼接？
- 多部位材质是否按 `部位:值;部位:值` 输出？
- `key_diff_point` 是否始终存在，并与 `result` 一致？
- JSON 围栏后是否仍完整包含`字段规则：`及其下方8条固定规则？缺少任一条都不得调用校验工具。
- 每个比价项是否默认只保留必要字段，所有额外条目都有本轮可信规则的直接依据且不与其他条目重复？

字段规则的8个必含语义逐项检查，不能只检查标题：

1. `extracted`仅包含按`category`生效的比价项；
2. `confidence`必须为`0.0`～`1.0`范围内的具体数字字面量；
3. 抽取不到时`value="缺失"`且`source=""`；
4. `source`只允许`商品属性`、`商品标题`、`主图`及其`+`组合；
5. `match`必须为布尔值并说明`true`、`false`含义；
6. 相同信息来自多个来源时使用`+`拼接；
7. 多部位材质使用`部位:值;部位:值`；
8. `key_diff_point`始终保留，并与`result`一致。
