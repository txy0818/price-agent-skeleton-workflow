# 用户描述的 Badcase

用户用文字、图片或商品信息描述 Badcase，但没有提供真实验证任务与 Case ID。
共享步骤见 [shared-steps.md](shared-steps.md)。

进入本流程立即锁定 `badcaseMode=DESCRIPTION`；后续步骤和工具响应不得修改该值。

## 必读

完整读取 [badcase-processing-workflow.md](badcase-processing-workflow.md)、
[badcase-attribution-policy.md](badcase-attribution-policy.md)、[rule-loading-policy.md](rule-loading-policy.md)、
[base-version-policy.md](base-version-policy.md) 和 [shared-steps.md](shared-steps.md)，再连续执行统一流程
`[B0]`～`[B8]`。只有“是否修改提示词=是”时，再读取
[edit-skeleton-workflow.md](edit-skeleton-workflow.md) 的 Diff 与确认门禁。基础提示词、用户输入、可信
类目的规则与必要映射以及 S3 均由统一流程查询或执行；本入口不得重复调用或改写。缺少可信类目或
决定性商品事实时由 `[B5]` 进入证据不足模板。任一必读文件读取失败时，只返回准确文件名和真实
读取错误。

- 证据不足：当轮输出缺失项和“证据不足”结论，不生成或校验提示词。
- 非提示词缺陷：当轮输出完整分析结论，不输出 Diff。
- 确认属于提示词缺陷：当轮继续生成候选完整正文、实际执行 `[S3]`，并在 `valid=true` 后输出带服务端原样 Diff 的修改提案；不得等待用户再次回复才生成提案。

## 查询与判断

1. 重新读取本轮业务上下文，锁定 `badcaseMode=DESCRIPTION`；不得从用户描述或历史消息替换页面
   当前 `promptVersionId`。
2. 按统一流程 `[B0]`～`[B3]` 完成入口校验、基础提示词查询、用户事实规范化，以及可信类目的规则
   与必要映射查询。所有 MCP 名称、参数和响应门禁只以统一流程为准，本入口不复制、删减、改名或
   绕过；本模式不查询 CDN。
3. 按 `[B4]`～`[B6]` 建立证据、执行充分性门禁并选择唯一一级分类；缺少可信类目或决定性事实时
   输出“待核验（证据不足）”，不得猜测；人标或模型任一侧不确定时输出“待核验（标签不确定）”。
4. 按 `[B7]` 选择唯一分支：仅“是否修改提示词=是”时生成完整候选提示词并执行 `[S3]`；其余不得
   生成候选正文或调用校验工具。
5. 按 `[B8]` 使用下方对应模板输出；首条可见回复只能是固定分析结果或明确工具/数据错误。

## 输出

按 `[S4]` 展示。以下两个模板不是示例，而是本流程仅允许的可见回复协议；必须先按修改门禁
选择唯一分支，再逐项、按序套用。回复必须以 `## Badcase 初步分析` 为第一行，模板前后不得
添加任何文字，禁止合并模板或保留条件占位符。本场景没有真实验证任务，不输出或编造 CDN。

### 输出硬校验

发送前逐项检查；任一项不满足就在内部重组回复，不向用户展示错误版本：

1. 第一行必须严格等于 `## Badcase 初步分析`，模板前后不得添加文字。
2. 必须保留所选模板的全部字段、三级标题和顺序；禁止增加任务概览、CDN、耗时、Token、
   自由发挥的下一步说明或修改方向选项。
3. 输出前必须存在本轮真实基础提示词查询。除“缺少可信 categoryId 或决定性商品事实”的证据不足
   分支外，还必须存在争议类目的规则及规则实际要求的必要映射查询；免查询分支只能使用非提示词
   缺陷模板，类型固定为“证据不足”，依据必须逐项列出缺失内容，不得输出规则结论、Diff 或确认话术。
4. 一级分类只能是三类之一；未通过门禁时写对应“待核验”结果。只有第 2、3 类且具体原因直接
   定位到提示词缺陷时写“是”并使用缺陷模板；其余写“否”并使用非缺陷模板。
5. 模板中的一级分类、SKU/SPU 口径依据、具体原因、处理建议和是否修改提示词必须逐项复制 `[B6]`、
   `[B7]` 已形成的内部分析记录；输出阶段不得重新分类或改变分支。
6. 非缺陷模板不得出现 Diff、`diff_id`、S3 成功话术或确认话术；缺陷模板必须存在本轮真实
   `tool_validate_prompt_skeleton` 成功调用记录，展示同次响应的非零 `data.diff_record_id` 并原样
   输出同次 `data.diff_content`，否则禁止输出缺陷模板。
7. 两个模板都不得出现 CDN 链接、真实任务 ID/Case ID 占位字段或任何条件分支占位符。

## 确认后

只有证据充分、确认属于提示词缺陷且用户紧邻确认，才执行 `[S5]` 的 EDIT 路径。
