# 用户描述的 Badcase

用户用文字、图片或商品信息描述 Badcase，但没有提供真实验证任务与 Case ID。
共享步骤见 [shared-steps.md](shared-steps.md)。

## 提取与查询

1. 按 [base-version-policy.md](base-version-policy.md) 确定并查询基础提示词版本。
   本流程没有任务上下文自带的提示词，本轮未提供 ID 或名称时必须要求用户补充。
2. 从本轮输入提取左右商品标题、属性、主图、人工标签、模型结论和模型理由；
   不得把缺失信息补写成事实。
3. 执行 `[S2]` 加载规则与映射：`include_special_rule=1`；能从本轮输入确定类目时
   `category_ids` 传该类目，否则传空。本流程没有真实验证结果，因此没有 `raw_llm_response`
   可解析，争议比价项改从用户描述与已提取的商品差异判断，并对照取回的 `price_rule_json`
   与基础提示词 `## 比价项` 章节核对名称；对不上时向用户澄清，不擅自改写成相近名称。
   争议点涉及品牌或材质判定时才调用 `tool_query_rule_data_table`，且只传相关 `table_types`。
4. 判断证据是否足以复核争议比价项：涉及外观必须有左右主图；涉及标题、属性或映射必须有
   对应原始信息；必须知道人工标签与模型结论。信息不足时列出缺失项并停止，
   不生成 Diff 或草稿。
5. 信息充分时结合规则、映射和基础提示词复核。可能是提示词缺陷、模型未遵循规则、
   疑似人工标签错误、映射或数据问题、证据不足，不得默认归因于提示词。
6. 仅在确认属于提示词缺陷时执行 `[S3]` 生成并校验完整提示词；否则不生成、不校验。

## 确认后

只有证据充分、确认属于提示词缺陷且用户明确确认，才执行 `[S5]`，
`prompt_version_id` 传基础提示词 ID。
