# 用户描述的 Badcase

用户用文字、图片或商品信息描述 Badcase，但没有提供真实验证任务与 Case ID。
共享步骤见 [shared-steps.md](shared-steps.md)。

## 执行门禁

输出前必须读取并按顺序执行 [badcase-processing-workflow.md](badcase-processing-workflow.md) `[B0]`～
`[B8]` 及其要求的共享步骤、版本、规则和归因规范，并精确查询当前 `promptVersionId`。具备可信类目
和必要商品事实时执行 `[S2]` 后完成八类归因；缺少可信类目或决定性商品事实时不得猜测、不得调用
规则/映射 MCP，直接使用证据不足模板列出缺失项。不得只报告“已加载流程”或预告下一步。

- 证据不足：当轮输出缺失项和“证据不足”结论，不生成或校验提示词。
- 非提示词缺陷：当轮输出完整分析结论，不输出 Diff。
- 确认属于提示词缺陷：当轮继续生成候选完整正文、实际执行 `[S3]`，并在 `valid=true` 后输出带服务端原样 Diff 的修改提案；不得等待用户再次回复才生成提案。

## 提取与查询

1. 仅当业务上下文缺少 `ruleGroupId` 时执行 `[S1]`；已有则跳过。随后按
   [base-version-policy.md](base-version-policy.md) 确定并查询基础提示词版本。
   只使用当前业务上下文的 `promptVersionId`；缺失或为 0 时直接说明尚未初始化并停止，不向用户
   索取 ID 或名称。
   查询结果的 `prompt_content` 必须非空；为 `null`、空串或仅空白字符时立即停止，说明该
   提示词尚未初始化，不能进行 Badcase 归因或修改，并建议先进入初始化提示词流程。
   非空时记录 `selectedPromptVersionId=data.prompt_version.prompt_version_id`，要求大于 0，
   并锁定 `writeMode=EDIT`。
2. 从本轮输入提取左右商品标题、属性、主图、人工标签、模型结论和模型理由；
   不得把缺失信息补写成事实。
3. 先从本轮可信业务上下文或用户提供的可验证结构化字段取得真实 `categoryId`；禁止从标题、图片、
   商品描述、提示词或模型知识猜测。取得后按 `[S2]` 加载争议范围内的规则与必要映射。本流程没有
   真实验证结果，争议项从用户描述与商品差异判断，并与类目规则、基础提示词章节核对；名称对不上
   时先澄清，不改写成近义词。没有可信 `categoryId` 时跳过 `[S2]` 并进入证据不足固定分支。
4. 判断证据是否足以复核争议比价项：涉及外观必须有左右主图；涉及标题、属性或映射必须有
   对应原始信息；必须知道人工标签与模型结论。信息不足时列出缺失项并停止，
   不生成 Diff 或草稿。
5. 将用户本轮提供的事实整理成统一内部分析记录；缺失字段保持为空。按统一流程
   `[B4]`～`[B6]` 建立证据、执行充分性门禁并选择唯一一级归因，不得默认归因于提示词。
   若基础提示词已经明确要求某条件下的结论，而模型结论或理由与之相反，只有同时满足以下条件才
   归为“模型未遵循规则”：商品事实充分，且用户提供的模型分析过程能证明争议事实已被正确抽取。
   模型分析过程证明漏抽/错抽时归为“模型抽取或推理异常”；未提供足以确认抽取是否正确的模型分析
   过程时归为“证据不足”。不得仅凭最终结论或模型理由判定“模型未遵循规则”。
6. 严格执行统一流程 `[B7]`：只有一级归因为“提示词规则缺陷”才生成候选完整提示词并实际执行
   `[S3]`；其他七类不生成候选正文、不调用校验工具。随后按 `[B8]` 选择下方唯一固定模板。

## 输出

按 `[S4]` 展示。以下两个模板不是示例，而是本流程仅允许的可见回复协议；必须先按归因结果
选择唯一分支，再逐项、按序套用。回复必须以 `## Badcase 初步分析` 为第一行，模板前后不得
添加任何文字，禁止合并模板或保留条件占位符。本场景没有真实验证任务，不输出或编造 CDN。

`[S3]`，不输出 Diff 或确认话术。

- 右侧商品：<标题、属性和主图信息>

### 输出硬校验

发送前逐项检查；任一项不满足就在内部重组回复，不向用户展示错误版本：

1. 第一行必须严格等于 `## Badcase 初步分析`，模板前后不得添加文字。
2. 必须保留所选模板的全部字段、三级标题和顺序；禁止增加任务概览、CDN、耗时、Token、
   自由发挥的下一步说明或修改方向选项。
3. 输出前必须存在本轮真实基础提示词查询。除“缺少可信 categoryId 或决定性商品事实”的证据不足
   分支外，还必须存在争议类目的规则及规则实际要求的必要映射查询；免查询分支只能使用非提示词
   缺陷模板，类型固定为“证据不足”，依据必须逐项列出缺失内容，不得输出规则结论、Diff 或确认话术。
4. 类型只能是八类之一并与分支一致：只有“提示词规则缺陷”写“是”并使用缺陷模板；其他七类
   一律写“否”并使用非缺陷模板。
5. 提示词已明确规则而模型结论或理由相反时，仍必须验证商品事实充分且模型已正确抽取争议事实；
   满足后才归为“模型未遵循规则”。模型漏抽/错抽归为“模型抽取或推理异常”，缺少模型分析过程归为
   “证据不足”；三种情况都不得生成 Diff。
6. 非缺陷模板不得出现 Diff、`diff_id`、S3 成功话术或确认话术；缺陷模板必须存在本轮真实
   `tool_validate_prompt_skeleton` 成功调用记录，展示同次响应的非零 `data.diff_record_id` 并原样
   输出同次 `data.diff_content`，否则禁止输出缺陷模板。
7. 两个模板都不得出现 CDN 链接、真实任务 ID/Case ID 占位字段或任何条件分支占位符。

## 确认后

只有证据充分、确认属于提示词缺陷且用户紧邻确认，才执行 `[S5]` 的 EDIT 路径。
