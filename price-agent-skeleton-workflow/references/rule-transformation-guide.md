# 比价项转换规范

本文件是比价项正文生成与校验的唯一规范，不是候选提示词正文。候选中只呈现转换后的业务内容，
不得复制本文件的门禁、算法、`expectedPriority` 或 `expectedMatch` 等内部术语。

## 1. 权威输入

- 比价项、顺序、类目、`infoSource`、`compareLogic`、`specialRuleContent.ruleContent` 只取本轮
  `radar_query_price_rule.data.labelCateRule`。
- 五种固定 `compareLogic` 的完整语义只取 [enums.md](enums.md)，本文件不重复定义。
- 母子品牌和材质附录只取 [rule-loading-policy.md](rule-loading-policy.md) 规定的关系查询结果。
- 输入缺失或无法解析时停止；不得用旧提示词、示例或模型常识补齐。

## 2. 比价项集合与适用类目

按 `ruleTableInfo.ruleTableInfo[]` 原顺序生成比价项。每个真实 `compareItem` 必须同时对应：

1. 顶部适用类目表中的一行；
2. `## 比价项` 下的一个独立章节；
3. 输出 JSON `extracted` 中的一个同名字段。

三处的数量、名称和顺序必须完全一致，不得合并、拆分、改名或新增。顶部表格每个比价项独占一行，
适用类目取本轮 `labelCateRule.cateNameTree`，只把 `/` 转为 `>`。

适用类目只在顶部表格出现。每个 `### N. <compareItem>` 章节禁止再写
`- **适用类目**`。

## 3. 每个比价项的唯一正文结构

普通比价项只写：

```markdown
### N. <真实 compareItem>

- **优先级**：<expectedPriority>
- **匹配**：<清洗后的特殊规则 + 真实 compareLogic 兜底>
```

不得再增加“适用类目”“抽取规则”“归一化规则”“规则名称”等重复字段。

当且仅当真实比价项集合包含“材质”时，材质章节在“匹配”之后额外增加一个同级条目：

```markdown
- **材质对照表**：见下方附录。
```

这行是附录引用，不属于“匹配”，不得缩进到“匹配”的子项目中，也不得计入 `expectedMatch`。

## 4. 优先级：只做原序过滤

对每项原始 `infoSource` 从左到右做稳定投影：

1. 最终只允许三个标准来源：`商品属性`、`商品标题`、`主图`。
2. **先拆最小来源片段**：从左到右扫描完整 `infoSource`，将 `>`、`/`、`=` 都视为来源边界，拆成
   最小来源片段后再过滤。不得先把 `>` 之间的整段作为一个节点删除；同一大段中以 `/` 或 `=` 分隔的
   合法来源必须单独保留。冒号只分隔说明或来源链，不改变后续片段的原始先后顺序；扫描冒号前后全部
   内容，不得截断第二段来源链。
3. **逐片段删除 SKU**：任一最小来源片段只要包含大小写不敏感的连续字样 `sku`，该片段直接删除；即使该片段
   同时包含`商品属性`、`商品标题`或`主图`也不得保留或归一。例如`SKU商品标题`、`sku图主图文字说明`、
   `商品属性（SKU）`均删除。
4. 对剩余片段做白名单包含匹配：包含连续字样`商品属性`的片段归一为`商品属性`；包含连续字样
   `商品标题`的片段归一为`商品标题`；包含连续字样`主图`的片段归一为`主图`。例如
   `商品属性栏`→`商品属性`、`站外商品标题`→`商品标题`、`主图文字说明`→`主图`。
   方向、站点和括号限定不影响包含匹配：`商品属性栏（站外）`、`商品属性（站外）`、
   `站外商品属性栏`均必须归一为`商品属性`。禁止因为片段含“站外”“栏”或括号而删除。
5. 对未命中上述三个连续字样的片段，删除比价维度、比价系统品牌/等级、商品详情、详情图、编码、
   包装等非白名单来源；不得把被删除来源改写成三个白名单来源。例如`详情图文字说明`不含连续字样
   `主图`，必须删除。
6. 保留剩余来源在完整原文中的相对顺序，按首次出现位置去重并用 `>` 连接，清理空分隔符。禁止按模型认为的可靠性重排，
   禁止补入原文不存在的来源。
7. 过滤后没有任何合法来源时，固定写
   `综合判断（商品标题/商品属性/主图同等参考）`。

内部生成 `expectedPriority`，候选“优先级”必须与其完全一致。白名单不是必填清单：过滤后只有一项
就写一项，只有两项就写两项。

例如：

- `商品属性>比价维度/商品标题` → `商品属性>商品标题`，不得补`主图`；
- `比价维度>sku图文字说明>商品标题>主图文字说明>商品属性栏>商品详情`
  → `商品标题>主图>商品属性`，不得重排为`商品属性>主图>商品标题`。
- `SKU商品标题>主图文字说明>商品属性（SKU）` → `主图`；两个含 `SKU` 的节点整体删除，
  `主图文字说明`归一为`主图`。
- `sku图中商品本身品牌信息=比价系统品牌/等级（站内）/商品属性栏（站外）>商品标题>商品详情`
  → `商品属性>商品标题`；只删除含 SKU 的最小片段，不能连带删除同一大段中的`商品属性栏（站外）`。

上述品牌来源链是强制解析用例。生成账本时必须逐片段保留：
`sku图中商品本身品牌信息(删除)`、`比价系统品牌(删除)`、`等级（站内）(删除)`、
`商品属性栏（站外）(商品属性)`、`商品标题(商品标题)`、`商品详情(删除)`；最终
`expectedPriority` 必须逐字符等于 `商品属性>商品标题`。得到 `商品标题` 或其他结果时说明拆分或
归一错误，必须内部重算，不得生成候选或调用 S3。

示例只说明算法，不是任何比价项的固定业务事实。

## 5. 匹配：特殊规则 + 兜底规则

每项“匹配”只能按以下顺序组成：

1. 从 `specialRuleContent.ruleContent` 取能明确归属该真实 `compareItem` 的全部专属规则；
2. 删除其中所有 SKU 来源、SKU 图片、SKU 标题、SKU 包装等内容。混合句删除后语义不完整时整句删除，
   禁止把 SKU 改写为主图、商品标题或商品属性；
3. 最后追加该项真实 `compareLogic`。先按 [enums.md](enums.md) 的受控别名精确归一，再展开对应
   标准枚举。没有专属规则时仍必须写兜底；`compareLogic` 未定义或为空时也只按 `enums.md` 处理。

同一编号下的子项、阈值、默认值、例外和示例必须跟随所属特殊规则，不得截断。无法唯一归属某个
已有比价项但影响多项的特殊规则写入“总原则”，不得新建比价项。

内部生成 `expectedMatch=清洗后的全部专属规则 + 真实兜底`，候选必须逐条一致。禁止根据比价项名称、
旧提示词或模型常识补写规则，例如“合理误差”“佩戴效果”“整体认知”“赠品/配件”“商品价值”
“使用体验”“左有右无”等；只有本轮特殊规则或固定枚举明确提供时才能出现。

## 6. 三类特殊结构

### 品牌

- 品牌章节仍只使用统一正文结构，匹配仍是“品牌专属规则 + 品牌真实 `compareLogic` 兜底”。
- 不能因为名称是“品牌”就自行添加母子品牌互认、中英文互认或直接判同规则。
- 当且仅当真实比价项集合包含“品牌”时，按 [rule-loading-policy.md](rule-loading-policy.md) 查询母子
  品牌关系；无“品牌”时禁止查询和输出。附录不能代替品牌的特殊规则或兜底。
- 先校验工具返回的全部有效组，再结合本轮 `cateName`、`cateNameTree`、`belongBusiness` 和模型常识
  做保守过滤。只保留主营范围能确认与当前类目直接相关的组；跨行业、测试数据、不确定或仅名称
  看似相关的组必须删除。模型常识只用于从真实返回中删除不相关组，不得用于新增、补别名、合并、
  修改母品牌或修改子品牌。
- 必须先遍历全部返回、再完成类目和常识过滤、最后应用数量上限；禁止先取前 100 组再过滤。模型
  自行查询和生成时最多输出 **100 个主品牌组**，不足 100 组只输出实际命中组，不得补齐。过滤后
  超过 100 组时优先保留主营范围与当前类目直接相关且在该类目更常见的组；仍无法区分时保持工具
  原顺序。
- 每组必须逐项来自本轮工具响应，格式固定为
  `序号. 母品牌→子品牌1|子品牌2`。每个主品牌组独占一行；不得用顿号、逗号、斜杠、加粗或无序
  列表替代该格式，相同母品牌不得拆成多组。
- 过滤、删除或替换任一组后，必须丢弃全部旧序号，保持剩余组当前顺序，从 1 开始整体重写为连续
  `1..N`。例如删除第 6 组后，原第 7 组必须成为第 6 组；禁止出现空序号、跳号或重复号。
- 过滤结果为 0 组时静默省略品牌映射表，不得输出空结果说明或用低相关组补齐。
- 用户明确指定某组的新增、删除、替换或成员调整属于精确修改，直接执行用户指令，不查询关系库
  复核；明确新增不受模型自行生成时的 100 组上限限制，也不得为了降回 100 组删除原有关系。删除
  或替换后仍必须重新生成连续序号。

### 材质

- 材质章节仍按统一规则生成优先级和匹配，不得自行添加“主材质一致”“同组即匹配”“影响价值”
  “左有右无”等话术。
- 过滤后存在有效材质组时，才额外增加独立的`材质对照表`引用并按
  [rule-loading-policy.md](rule-loading-policy.md) 输出附录；为空时引用和附录都省略。
- 材质组必须来自同一真实直接父节点下的 `isLeaf=true` 叶子，组名使用从一级根节点到该父节点的
  完整路径并以`·`连接；不得把中间类别或不同父节点的后代压平为一组。过滤结果允许为空，空时静默
  省略材质引用和附录，不得编造。

### 货号

- 不能因为 `compareItem` 名称是“货号”就添加货号例外。
- 仅当该项真实 `compareLogic=货号匹配逻辑` 时，按 [enums.md](enums.md) 展开，并同步使用其中规定的
  Step3 综合判定例外。
- 货号章节不增加额外格式字段。

## 7. 进入 S3 前硬校验

- 比价项表格行、章节和 `extracted` key 与真实集合数量、名称、顺序完全一致。
- 比价项章节中不存在`适用类目`，普通项只有`优先级`和`匹配`。
- 每项候选优先级与 `expectedPriority` 完全一致，没有补来源或重排。
- 每项候选匹配与 `expectedMatch` 完全一致，顺序为特殊规则在前、兜底在后，没有模型补写。
- 命中 `enums.md` 受控别名时已展开为标准枚举完整语义，候选中没有残留别名原文。
- 候选不含任何大小写形式的 SKU 内容。
- 有材质时，独立引用与附录同时存在；无材质时二者都不存在。
- 品牌映射非精确修改时不超过 100 组，均来自本轮响应并通过类目与常识过滤；删除后序号连续。
- 品牌、材质和货号只触发本节规定的附加结构，不互相借用规则。

任一项不满足时直接判错，不得调用 S3。
