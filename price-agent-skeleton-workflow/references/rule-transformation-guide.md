# 规则转换指南

用于从 MCP 返回的规则 JSON 生成同款判定提示词。这里只规定转换方法，不提供当前业务事实。

## 权威输入

只使用以下业务内容：

- `radar_query_price_rule.data.labelCateRule`：类目、业务线、搜索方式、比价项、信息来源、匹配逻辑和 `specialRuleContent.ruleContent`。
- 当前 MCP 清单中实际存在的主子品牌关系查询结果：经可信关键词和当前作用域约束后的关系。
- `radar_query_material_relation`：按当前 `cateName`、`belongBusiness` 过滤后的同款材质关系。

JSON 缺失、为空或无法解析时停止，不使用参考示例补齐。本指南不用于用户已明确指定具体文本的
精确修改直达分支。

## 转换步骤

1. 从 `labelCateRule.ruleTableInfo.ruleTableInfo[]` 提取当前类目的比价项列表。一个 `compareItem` 对应提示词中的一个比价项章节，以及输出 JSON `extracted` 中的一个字段。
   名称与顺序原样保留；例如返回“品牌、材质、尺寸、外观、数量、重量”时只能生成这 6 项，禁止
   改成“品牌&系列”“材质&成分”，也禁止拆出主石、副石、金属重量、圈口或货号等新项。
2. `infoSource` 非空时转成一条“优先级”，保留原始 `>`、`=`、`/`、左右侧差异和兜底条件，不改序、不解释。
3. `compareLogic` 非空时写入“匹配”。值仅为“通用匹配逻辑”“严格匹配逻辑”等名称时原样写入，禁止扩写其含义。
4. 完整解析 `specialRuleContent.ruleContent`：
   - 明确点名已有 `compareItem`，或从内容可唯一判断归属已有比价项的规则，写入该项“匹配”；
   - 普通比价项只保留影响判定的条件、阈值、默认值和边界，用短句或子项目符号表达；
   - “品牌”和“材质”是展开例外：除“优先级”“匹配”外，完整保留可信输入中的具名规则、抽取格式、互认/交集规则、缺失或无效值、阈值、特殊边界及有助于消歧的示例，不因篇幅压缩；
   - 同一主题的后续项目符号与上一条规则合并，不能丢失；
   - 没有对应 `compareItem` 或同时影响多个比价项的规则写入“总原则”，不得据此新建比价项或 `extracted` 字段；
   - 能归属已有比价项的规则不能只放在总原则；品牌和材质不得因精简而丢失具名条目或示例；
   - 不得从特殊规则反推出未返回的阈值、默认值、风险或行业常识。
   - 该字段为空、缺失或仅空白时跳过本步骤，禁止产生任何特殊规则内容。
5. 主子品牌与材质关系只使用 [rule-loading-policy.md](rule-loading-policy.md) 的最终过滤结果；
   每个输出组及其成员都必须能在本轮关系工具响应中逐项找到，工具返回总组数只是可选数据上界，
   不是生成目标；例如返回 192 组时，输出只能是其中经过当前类目过滤且符合既定上限的子集，禁止
   为凑满 192 组复制全量、跨类目关系或凭常识补写。母品牌或子品牌为空的组不得输出。数据范围、
   上限和精确修改例外不在此重复。母子品牌按 `序号. 母品牌→子品牌1|子品牌2` 输出。
6. 按 [skeleton-format.md](skeleton-format.md) 生成角色、输入说明、执行步骤、判定规则、映射表、图片说明和 JSON 输出格式。

## 简短示例

输入：

```json
{
  "compareItem": "品牌",
  "infoSource": "sku图品牌=商品属性>商品标题",
  "compareLogic": "通用匹配逻辑"
}
```

转换：

```markdown
### 品牌

- **优先级**：sku图品牌=商品属性>商品标题
- **匹配**：通用匹配逻辑
```

特殊规则输入：

```text
1. 版本：儿童版与成人版不可相互匹配。
```

转换到对应比价项：

```markdown
- **匹配**：儿童版与成人版不可相互匹配。
```

不得因此额外生成输入中没有的“系列”“抗菌等级”等比价项。

例如类目规则已包含“能效等级”，特殊规则为“能效等级：一级、二级、三级、四级等”，应合并为：

```markdown
### 能效等级

- **优先级**：比价维度>sku图>商品标题>主图>商品属性
- **匹配**：优先完美匹配逻辑；能效等级包括一级、二级、三级、四级等
```

“包安装商品和不包安装商品不可匹配”没有现成比价项时，只能写入总原则；其后续项目符号继续归入同一条：

```markdown
6. 包安装商品和不包安装商品不可匹配；出现上门安装但未说明费用时，默认包安装。
```

不得因此新增“安装服务”等比价项。除上述真实字段外不得增加风险分析、价格影响、允许偏差或
缺失值规则。

多条规则归属同一比价项时，压缩到同一个“匹配”栏目，允许使用子项目符号：

```markdown
### 货号

- **优先级**：综合判断（商品标题/商品属性/主图同等参考）
- **匹配**：
  - 货号不一致或缺失时，不得仅凭货号判 `different`，继续判断其他项
  - 忽略符号后一致即可匹配
  - 除货号外其他项均匹配时，必须判 `same`
```

上述压缩格式适用于品牌、材质以外的普通比价项。品牌和材质按完整展开例外处理。

## 完成检查

- 每个有效 `compareItem` 是否恰好生成一个章节和一个 `extracted` 字段？
- 是否遗漏或改变 `infoSource` 的优先级与左右侧差异？
- 是否把逻辑名称误写成未经查询的详细规则？
- 是否逐条消费 `specialRuleContent.ruleContent`，明确点名或语义唯一归属项写入已有比价项、其余写入总原则？
- 是否把特殊规则错误生成为新比价项或新的 `extracted` 字段？
- 是否捏造了“微小偏差”“影响价格”“信息缺失默认”等查询结果中不存在的细则？
- 是否只使用关系工具真实返回且通过当前类目、业务线过滤的映射？
- 映射是否完全使用 `rule-loading-policy.md` 的最终结果？
- 母子品牌是否使用连续序号、`→` 和 `|`，且没有加粗、无序列表或冒号？
- 是否加入了输入 JSON 没有的比价项、阈值或业务事实？
