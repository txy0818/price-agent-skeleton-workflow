# 规则转换指南

本文件全部内容都是生成器内部转换与校验规范，不是 PriceStudio 候选提示词正文。以下关于字段来源、
顺序、独占行、路径转换、禁止合并及集合校验的说明只能在内部执行，禁止逐句复制、改写、概括或作为
“规则说明”写入 `prompt_content`；最终正文只呈现转换后的真实比价项、真实适用类目和业务规则。

用于从 MCP 返回的规则 JSON 生成同款判定提示词。这里只规定转换方法，不提供当前业务事实。

## 权威输入

只使用以下业务内容：

- `radar_query_price_rule.data.labelCateRule`：类目、业务线、搜索方式、比价项、信息来源、匹配逻辑和 `specialRuleContent.ruleContent`。
- 当前 MCP 清单中实际存在的主子品牌关系查询结果：经可信关键词和当前作用域约束后的关系。
- `radar_query_material_relation`：按当前 `cateName`、`belongBusiness` 过滤后的同款材质关系。

JSON 缺失或无法解析时停止，不使用参考示例补齐；材质关系成功响应中的空节点集合是允许的真实
结果，按材质空附录规则继续。本指南不用于用户已明确指定具体文本的
精确修改直达分支。

## 转换步骤

1. 从 `labelCateRule.ruleTableInfo.ruleTableInfo[]` 提取当前类目的比价项列表。一个 `compareItem` 对应提示词中的一个比价项章节，以及输出 JSON `extracted` 中的一个字段。
   名称与顺序原样保留；例如返回“品牌、材质、尺寸、外观、数量、重量”时只能生成这 6 项，禁止
   改成“品牌&系列”“材质&成分”，也禁止拆出主石、副石、金属重量、圈口或货号等新项。
   输入说明的适用类目表也必须按相同顺序每个 `compareItem` 独占一行；即使适用范围相同，也禁止
   合并成 `|品牌、材质、尺寸、外观、数量、重量|...|`。每行适用类目取本轮真实
   `labelCateRule.cateNameTree` 并把 `/` 转为 `>`；例如 `家用电器/大家电/冰箱` 写成
   `家用电器>大家电>冰箱`，禁止写“全类目”或自行简称。
   生成后执行集合硬校验：设 `C=ruleTableInfo[].compareItem`，则适用类目表行名、Step0 项数、
   `### N. 比价项` 标题和 JSON `extracted` key 必须与 `C` 数量、名称、顺序完全一致。任何多出、
   缺少、改名或合并都不合格；`SPU`、`核心比价项` 等名称只有在 `C` 原样包含时才能出现。
   `C` 精确包含“材质”时，该比价项章节必须额外写固定结构引用
   `- **材质对照表**：见下方附录。`，并在下方输出材质对照表附录；二者缺一均不合格。过滤后为
   0 组时附录写固定空结果说明，不得编造材质或停止生成。
   该固定引用不是匹配规则，不加入 `expectedMatch`。`C` 不含“材质”时禁止输出引用和材质附录。
2. 对每个 `infoSource` 生成“优先级”时执行允许来源投影，而不是复制原文：
   - 最终只允许三个规范来源名：`商品属性`、`商品标题`、`主图`。将“商品属性栏”“属性项栏”
     “属性栏”“站内商品属性栏”“站外商品属性栏”“商品属性栏（站内）”“商品属性栏（站外）”
     及仅附带站内/站外限定的同一字段规范为`商品属性`；将“商品主图”“主图文字说明”“主图文字”
     “主图中的文字说明”“主图中的文字”“主图中”“主图商品文字说明”“主图综合判断”及明确表示
     信息来自商品主图或主图文字的同义表达规范为`主图`。“综合判断”只表示参考方式，不是来源名，
     不得作为来源节点保留。除此之外不做近义改写。归一时只删除字段名附带的站内/站外说明，不得
     把“比价系统品牌/等级”等其他站内字段一并归为`商品属性`；`sku图文字说明`和`详情图文字说明`
     仍分别属于 SKU 与详情来源，必须删除，不得因同样含有“文字说明”而归为`主图`。
   - 删除所有不在上述白名单中的来源节点、限定语和说明，包括任意大小写形式的 SKU、`sku图`、
     `sku标题`、`sku图文字说明`、`sku图商品外包装`、`比价维度`、`比价系统品牌/等级`、`商品详情`、
     `详情图`、编码及站内外说明；禁止把被删除来源改写成白名单来源。
   - 解析 `>`、`=`、`/` 及换行表达的来源关系，只保留白名单来源的原始相对优先级；同级使用 `/`，
     不同优先级使用 `>`，去重并清理空节点、首尾和相邻分隔符。不得保留原始来源附带的解释句。
   - 原文使用“结合”“综合判断”“同等参考”等表达且没有为保留下来的来源明确给出先后顺序时，
     将命中的白名单来源用 `/` 连接并放入`综合判断（...同等参考）`；例如“结合商品标题、商品属性栏、
     主图综合判断”生成`综合判断（商品标题/商品属性/主图同等参考）`。原文已有明确 `>` 优先顺序时
     保留该顺序，不得改成综合判断。
   - 过滤后仍有白名单来源时，输出过滤后的真实相对顺序；过滤后一个白名单来源都不剩时，固定输出
     `综合判断（商品标题/商品属性/主图同等参考）`。每个比价项都必须保留一条“优先级”，不得删除。
   - 对每项建立内部 `expectedPriority`，严格执行稳定投影：从原文左到右解析来源节点与原始层级，
     删除非白名单节点，将保留节点规范为三个来源名；同一规范名重复出现时只保留第一次及其所在
     层级；最后只清理因删除产生的空层级和分隔符。禁止交换任意两个保留节点，禁止依据模型认为的
     可信度、常见优先级、比价项名称、旧提示词或其他比价项重新排序，也禁止补入原文没有的来源。
     候选正文“优先级”必须与 `expectedPriority` 完全一致。
   - 例如原文为
     `比价维度>sku图商品外包装>sku图中的文字描述>商品标题>主图>商品属性栏>商品详情`，稳定投影
     只能得到 `商品标题>主图>商品属性`；不得写成 `商品属性>主图>商品标题`。`商品属性栏`最终统一
     写为规范名`商品属性`。本例只用于证明过滤算法，不得作为任何真实比价项的业务事实复制。
3. 先完整解析 `specialRuleContent.ruleContent`，按已有 `compareItem` 建立专属规则集合：
   - 明确点名已有 `compareItem`，或从内容可唯一判断归属已有比价项的规则，完整归入该项“匹配”；
   - 同一编号下的后续 `a/b/c`、项目符号、示例、阈值和特殊场景均属于该比价项，不得截断或拆散；
   - 普通比价项保留所有影响判定的条件、阈值、默认值、优先级和边界，可整理为短句或子项目符号；
   - “品牌”和“材质”继续执行完整展开例外，保留具名规则、抽取格式、互认/交集、无效值、阈值、
     特殊边界和消歧示例；
   - 没有对应 `compareItem` 或同时影响多个比价项的规则写入“总原则”，不得据此新建比价项或
     `extracted` 字段；
   - 不得从特殊规则反推出未返回的阈值、默认值、风险或行业常识。
   - 写入提示词前删除全部 SKU 相关内容，大小写不敏感。整条规则只描述 SKU 来源、SKU 图片、SKU
     标题或 SKU 包装时整条删除；混合规则只删除可独立分离的 SKU 短语，剩余语义不完整或含义发生
     改变时整条删除。禁止把 SKU 改写成主图、商品标题、商品属性或其他来源。
4. 为每个 `compareItem` 生成“匹配”时，只允许“特殊规则 + 真实兜底规则”，顺序固定：
   1. 先完整写入第 3 步归属该项的 `specialRuleContent.ruleContent` 专属规则；没有则省略本段；
   2. 最后追加该项真实 `compareLogic` 的兜底语义；即使已有专属规则也必须追加，不得二选一。

   除本轮 `specialRuleContent.ruleContent` 和该项真实 `compareLogic` 外，禁止根据比价项名称、完整示例、
   旧提示词或模型常识补写“完全一致”“缺失即不匹配”“母子品牌互认”“无关修饰词”“功效/对象”
   等匹配条件。品牌、材质、货号和其他比价项统一遵守本规则，不存在模型固定追加规则的例外。

   专属规则正文自身写有“按照通用/影响价格/严格/货号/优先完美匹配逻辑”时，在原位置展开对应固定语义，
   并继续保留全部后续细则；末尾仍按上述顺序追加该项的兜底逻辑，但相同句子逐字重复时只保留一次。

   以下五个枚举是固定兜底语义。展开时将“该比价项”自然替换为真实 `compareItem` 名称，使句子可
   直接执行；不得只输出逻辑名称，也不得自行补充阈值、默认值和行业判断：
   - `通用匹配逻辑`：左右两侧该比价项一致，或者信息不冲突，或者存在交集，即可匹配。
   - `优先完美匹配逻辑`：左右两侧该比价项一致或信息不冲突即可匹配；优先匹配比价项一致的竞品，
     没有一致竞品时，才可匹配信息不冲突的竞品。
   - `影响价格匹配逻辑`：左右两侧该比价项一致或信息不冲突即可匹配；优先匹配比价项一致的竞品；
     没有一致竞品时，判断该比价项差异是否影响价格，不影响价格才可匹配。
   - `严格匹配逻辑`：左侧有该比价项时，右侧必须有且一致才可匹配；左侧有、右侧无时不可匹配；
     左侧无、右侧有时可匹配。
   - `货号匹配逻辑`：货号不一致或缺失时，禁止仅凭货号判 `different`，必须继续判断其他生效比价项；
     可忽略符号，去除符号后一致即可匹配；除货号外其他生效比价项均 `match=true` 时必须判 `same`，
     货号不一致不构成否决。
     当且仅当本轮某项真实 `compareLogic=货号匹配逻辑` 时，还必须把“货号不一致不构成否决，除货号
     外其他生效比价项均匹配则判 `same`”同步写入 Step3 综合判定，避免通用“任一 false 即 different”
     与该兜底冲突；不得仅因 `compareItem` 名称是“货号”就添加此例外。
   其他非空 `compareLogic` 保留真实原文，不解释未定义名称。`specialRuleContent.ruleContent` 缺失，
   或去除首尾空白后为 `""`、`"-"`、`"—"` 时，只省略专属规则，仍逐项输出对应兜底逻辑。
   - 对每项建立内部 `expectedMatch`：按固定顺序拼接“完成 SKU 清洗后的该项全部专属规则”与“该项
     真实 `compareLogic` 的固定展开或未定义原文”。五个已定义枚举必须使用上方固定语义，不得换成
     近义行业规则；未定义名称只能原样作为兜底，不得猜测其最接近哪个枚举。
   - 从候选正文反向解析该项全部“匹配”条件，与 `expectedMatch` 逐条核对。候选中的每个条件、阈值、
     默认值、例外、示例和判断维度都必须能唯一追溯到专属规则或固定兜底；出现“合理误差”“佩戴
     效果”“整体认知”“商品价值”“使用体验”等响应未提供的模型补写语义时，立即判定不合格，禁止
     调用 S3。不得因为生成内容看似合理而保留。
   - 真实 `compareLogic=严格匹配逻辑` 时只能展开严格枚举，不能补充轻微差异或影响效果；真实
     `compareLogic=影响价格匹配逻辑` 时必须包含固定的价格影响回退，不能改写成整体认知；真实
     `compareLogic=通用匹配逻辑` 时只能展开通用枚举，不能补赠品、配件、误差或价值判断。
5. 主子品牌与材质关系只使用 [rule-loading-policy.md](rule-loading-policy.md) 的最终过滤结果；
   每个输出组及其成员都必须能在本轮关系工具响应中逐项找到，工具返回总组数只是可选数据上界，
   不是生成目标；例如返回 192 组时，输出只能是其中经过当前类目过滤且符合既定上限的子集，禁止
   为凑满 192 组复制全量、跨类目关系或凭常识补写。母品牌或子品牌为空的组不得输出。数据范围、
   上限和精确修改例外不在此重复。过滤完成后丢弃所有原序号和空条目，按剩余组当前顺序整体重写
   为连续 `1..N`；删除原第 42 组后，原第 43 组必须改为 42，后续依次前移。禁止保留空的
   `42.`、跳号或重复序号。母子品牌按 `序号. 母品牌→子品牌1|子品牌2` 输出。
   材质表必须按关系树的真实父子边生成：组名只取父节点自身名称，成员只取该父节点下至少两个
   `isLeaf=true` 的直接末端叶子；祖先路径不得出现在组名中。出现 `贵金属·天然宝玉石` 这类路径
   拼接名、把“贵金属”同时当组名和成员、或把真皮叶子挂到贵金属分支时，均直接判定候选不合格。
6. 按 [skeleton-format.md](skeleton-format.md) 生成角色、输入说明、执行步骤、判定规则、映射表、图片说明和 JSON 输出格式。

## 简短示例

输入：

```json
{
  "compareItem": "品牌",
  "infoSource": "sku图品牌=商品属性>商品标题",
  "compareLogic": "通用匹配逻辑"
}
```

转换：

```markdown
### 品牌

- **优先级**：商品属性>商品标题
- **匹配**：左右两侧品牌一致、信息不冲突或存在交集，即可匹配。
```

特殊规则输入：

```text
1. 版本：儿童版与成人版不可相互匹配。
```

转换到对应比价项：

```markdown
- **匹配**：儿童版与成人版不可相互匹配。
```

不得因此额外生成输入中没有的“系列”“抗菌等级”等比价项。

例如类目规则已包含“能效等级”，特殊规则为“能效等级：一级、二级、三级、四级等”，先写专属规则，
再追加“优先完美匹配逻辑”兜底：

```markdown
### 能效等级

- **优先级**：比价维度>商品标题>主图>商品属性
- **匹配**：能效等级包括一级、二级、三级、四级等；左右两侧能效等级一致或信息不冲突即可匹配；
  优先匹配能效等级一致的竞品，没有一致竞品时，才可匹配信息不冲突的竞品。
```

例如 `compareItem` 中存在“产地”，特殊规则为“产地：国内提取至省份，国外提取至国家。若无省份
或国家的表述，不冲突即可匹配”，且 `compareLogic=通用匹配逻辑`，则生成：

```markdown
- **匹配**：国内提取至省份，国外提取至国家；若无省份或国家的表述，不冲突即可匹配；左右两侧
  产地一致、信息不冲突或存在交集，即可匹配。
```

若“品牌”未在特殊规则中出现且其 `compareLogic=通用匹配逻辑`，只输出真实兜底，不得根据品牌
名称自行追加中英文、母子品牌、交集、缺失或示例规则：

```markdown
- **匹配**：左右两侧品牌一致、信息不冲突或存在交集，即可匹配。
```

“包安装商品和不包安装商品不可匹配”没有现成比价项时，只能写入总原则；其后续项目符号继续归入同一条：

```markdown
6. 包安装商品和不包安装商品不可匹配；出现上门安装但未说明费用时，默认包安装。
```

不得因此新增“安装服务”等比价项。除上述真实字段外不得增加风险分析、价格影响、允许偏差或
缺失值规则。

多条规则归属同一比价项时，压缩到同一个“匹配”栏目，允许使用子项目符号：

```markdown
### 货号

- **优先级**：综合判断（商品标题/商品属性/主图同等参考）
- **匹配**：
  - 货号不一致或缺失时，不得仅凭货号判 `different`，继续判断其他项
  - 忽略符号后一致即可匹配
  - 除货号外其他项均匹配时，必须判 `same`
```

上述“特殊规则 + 真实兜底规则”的格式适用于所有比价项，品牌、材质和货号也没有模型补写例外。

## 完成检查

- 每个有效 `compareItem` 是否恰好生成一个章节和一个 `extracted` 字段？
- 是否遗漏或改变 `infoSource` 的优先级与左右侧差异？
- 是否已逐项生成 `expectedPriority`，并确认候选值与稳定投影完全一致、没有重排或补来源？
- 候选提示词中是否仍出现任何大小写形式的 `sku`；如有则禁止进入 S3？
- 是否先逐条消费并按比价项归属 `specialRuleContent.ruleContent`，再为每个比价项追加对应兜底？
- 是否已逐项生成 `expectedMatch`，并确认候选中的全部匹配语义均可追溯且没有模型补写？
- 有专属规则的比价项是否同时保留了专属规则和兜底逻辑，且顺序正确？
- 每个比价项是否只写入本轮特殊规则和真实 `compareLogic` 兜底，没有按名称补写固定规则？
